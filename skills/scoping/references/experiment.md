# 観測で解消できる不明点

既存の資料・コード・ログ・テストで判断できず、結果によって方針が変わる場合だけ実験・試作・再現を選ぶ。観測前に判断したいことと、仮説を区別できる結果を定める。「動いた」だけで結論にしない。

問いに必要な最小の試作は本番コードから分離する。対象の版・環境・入力と適用限界を記録し、並行実行・中断・外部状態・永続化が問いなら、それを観測できる条件を選ぶ。模擬応答やインメモリでの成功を実システムの保証へ一般化しない。

未許可の外部操作や本番への書込みは行わない。許可された範囲で問いに答えられなければ、その限界と必要な判断を示す。

判断に足る根拠が得られたら止める。結果を区別できない場合や新しい根拠が得られない場合は、未確認事項と次に必要な調査・判断を残す。

結論・証拠・適用限界をIssue下書きへ反映し、再利用する根拠だけを[保存と改訂の手順](session.md#保存と改訂)でresearchへ残す。試作の成功を本実装・採用の完了とせず、[Issue反映の手順](issue.md)へ戻る。
