# IssueからPR作成

依頼や会話から対象Issueを特定する。対象Issueを特定できない場合は確認する。このスキルの実体から[development.ts](../../scripts/development.ts)を解決し、呼び出し元のrepoを指定して実行する。小さな変更と文書変更も合意済みIssueに紐づける。適用されるリポジトリ指示に従い、README・開発方針は今回の変更に関係する部分を参照する。[対象repoの設定](../../scripts/README.md#対象repoの設定)でcheckout・Issue・remote・公開先・base branch・検証・必要媒体を照合する。対象repoにBunやPlaywrightの構成を推測で追加しない。ハーネス自身はBunで実行する。

対象の設定や検証が未設定なら依存する実行を止める。要求変更は人の合意へ戻す。GitHubにはユーザーの既存gh認証でアクセスし、実効ユーザーと対象repoの権限を確認する。認証や権限が不足する場合は停止し、別の主体へ自動切替しない。

確認できる事実は調査し、ユーザーにしか分からない事実や未確定の意図・要求は早めに質問する。追加の合意や許可を求める前に、既に許可され、その判断に依存しない確認や案の作成を進め、判断対象と影響を示す。回答が必要な作業は回答まで止め、独立した作業は続ける。要求・公開範囲の合意とホストの実行条件を守り、スキルの一般的な進め方や説明方法よりユーザーの明示指示を優先する。指示文を理由に確認や停止が必要な場合は、実際に読んだ文書へのリンクと該当文を示し、明示された条件と自分の解釈を区別する。

実装前に[共通の文書利用手順](../references/documents.md#読む)で対象repoの関連wiki・判断記録を選び、Issueと現行コードへ照合する。差分が揃ったら[更新手順](../references/documents.md#残す更新する)で必要なwiki・DRの変更を独立評価へ含める。

文書のみの変更も同じ入口で扱う。実装に伴う更新と共通の[文書更新の方針](../../.codex/DEVELOPMENT.md#ドキュメントの更新)を適用する。何を変更するか未確定の相談やレビューだけの依頼は、その依頼の範囲で扱う。

テストを作成・更新する際、今回の失敗条件と既存検証の差を具体化する例が必要なら[テストを選ぶ参照資料](references/testing.md)を読む。該当条件がなければ追加テストや資料の一律読取はしない。

```sh
bun /absolute/path/to/trusted/scripts/development.ts 99 --repo /absolute/path/to/target-checkout
```

人が採用した既存PRの修正依頼も同じdevelopmentへ接続する。[既存PRの修正](../../scripts/README.md#既存prの修正)に従い、前回の公開run、既存checkout、採用した指摘・期待する結果・許可範囲をまとめた文章入力と新しい保存先を渡す。PRコメントを自動採用せず、旧runを再開しない。個別の検証設定や公開スクリプトは作らず、通常の修正・検証・独立評価・公開確認を使う。

開始前に[調査成果の引き継ぎ](../scoping/references/session.md#調査成果の引き継ぎ)で必要な根拠の内容・版・共有状態と合意範囲を確認し、[CLIの引き継ぎ手順](../../scripts/README.md#調査報告を指定した実装開始)へ渡す。Issueで選んだ共有モデルは[同じCLIの抽出経路](../../scripts/README.md#共有知識の選択)から初回実装・修正・独立評価へ渡るため、本文や選択を別ファイルへ転記しない。担当者は開始版と現在の差分の意味を評価し、判断に影響する不足を解消する。

執筆担当・独立評価担当・公開担当は、文書の作成・評価・draft公開後の本文確認で[日本語確認の方針](../../.codex/DEVELOPMENT.md#pr本文人向け文書の日本語確認)に従う。導入済みで旧設定のない通常作業では、上記の文書更新・日本語確認の方針と対象repoの現行方針を適用し、移行手順全体の毎回読取は求めない。

利用先への初回適用、旧版からの切替、旧`writing`設定などの旧設定を検出した場合は、対象repoの方針と[切替手順](../../scripts/README.md#専用校正の廃止と切替)の該当箇所を確認する。移行済みか不明なら、対象の設定・利用版・既存の受入記録など確認できる事実を調べ、未確認のまま移行済みと扱わない。方針や権限の判断が残る場合は、依存する切替・実行を止めて人へ戻す。

明示的な開発依頼は、検証・独立評価・検証済み対象の同一性確認を経たdraft PR作成、または対象の既存PRのdraft化と更新、その後の確認・ready切替までを含む。最初の実装だけで終了せず、ホストが担当する確認・修正・公開と下記の必要な公開後確認まで進める。合意済みの範囲内の作業ごとに許可を聞き直さない。「公開しない」指定は`--no-publish`へ渡し、独立評価までで終了する。スキルの自動選択だけを公開許可にせず、人の承認・マージは含めない。停止した実行は[結果と再実行](../../scripts/README.md#結果と再実行)で理由と残る条件を確認し、停止条件や上限を変更しての続行は禁止する。

公開後は[公開後確認とreadyへの切替](../../scripts/README.md#公開後確認とreadyへの切替)に従い、担当AIによる最新本文・必要媒体・同じheadのCI確認、ready直前の再照合と切替後の読戻しまで進める。CLI終了やCI成功を担当AIの確認完了と扱わない。PR URL、確認した版・検証結果、未確認事項、または停止理由と記録の場所を返す。
