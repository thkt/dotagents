# adrsの検索・判断履歴を試した結果

確認日: 2026-09-20（JST）。状態: 隔離試行完了、本導入は未実施。

## 結論

採用済みの判断を絞り込み、旧判断から置換先を辿る機能は動いた。日本語検索と読取り専用MCPも利用できた。一方、同じ答えは既存Issueと現行方針からも得られ、作業時間・誤判断・維持費用が改善するかは未評価。今回の結果だけでは本設定への登録を推奨しない。

試したNextGenモードの標準テンプレートでは、管理情報がacceptedでも本文にProposedが残った。MCPの全文取得にも両方が現れる。採用する場合は、記録と状態の更新方法を決め、この混同を防ぐ必要がある。

## 対象と方法

- 公式リリース [adrs v0.12.1](https://github.com/joshrotenberg/adrs/releases/tag/v0.12.1) のmacOS arm64バイナリを一時ディレクトリに展開。配布チェックサムと一致することを確認した。
- 公開済みの [Issue #84](https://github.com/thkt/dotagents/issues/84)、[Issue #128](https://github.com/thkt/dotagents/issues/128)、[Issue #149](https://github.com/thkt/dotagents/issues/149) を取得し、判断の一部分を3件の試験用ADRへ手動で要約した。ツールによる自動取り込みではない。
- #84のうちPR本文の意味確認を公開前後の責務に残した部分を旧判断、#128のdraft公開後へ集約する判断を置換先として扱った。#84全体を廃止扱いにしていない。現在の方針も [開発方針](../wiki/development-policy.md#pr本文人向け文書の日本語確認) と照合した。
- #149からはTanStack Markdownの選定候補だけを取り出し、proposedとした。HTML表示機能の要求への合意と、ライブラリの採用判断を区別した。
- `init`が生成するツール自身の採用記録1件は、比較対象の3件に数えていない。隔離環境内の記録であり、dotagentsでの採用合意ではない。
- 同じ元Issueの本文を直接読み、検索した場合とも比較した。執筆担当自身による機能確認で、初見の利用者や独立した評価モデルによる比較ではない。

## 確認結果

| 問い・操作 | 観測結果 | 判断への意味 |
| --- | --- | --- |
| 採用済みの公開方針を抽出 | `list --status accepted --tag publication`とMCPの`list_adrs`が新判断1件を返した | 旧判断・候補を一覧から除くことができる |
| 日本語で意味確認を検索 | `search --status accepted 意味確認`が新判断と本文の該当箇所を返した | 日本語を含む記録でも検索できた |
| 旧判断から置換先を取得 | `new --supersedes 2`で旧判断の状態と相互のリンクが更新され、MCPの`get_related_adrs`で置換先を取得できた | 関係を登録すれば経緯を辿れる。Issueを解析して自動で関係を発見したわけではない |
| TanStackは採用済みか | 通常検索では候補1件、accepted限定では0件。MCPの本文にも未決定と実装時の選定条件が残った | 保存した状態に基づく絞り込みは正しく動いた |
| MCPを読取り専用で起動 | `mcp serve --read-only`で11個の読取りツールを公開。検索・一覧・全文・関連・節別取得の計6呼出しが成功 | 永続設定を変えず、stdio経由の操作を確認できた。呼出し前後のADRファイルのハッシュは一致 |
| 元Issueから同じ答えを確認 | #128に変更理由と失う保証、#149に候補・未決定の記載があった | 今回はadrsだけで初めて得られた判断材料はない |

## 状態表示の不一致

本文を編集していない別の一時ディレクトリでも、次の最小手順で再現した。

```sh
adrs --ng init
adrs --ng new "Accepted metadata check" --status accepted --no-edit
```

生成ファイルのYAML frontmatterは`status: accepted`だが、本文の`## Status`は`Proposed`だった。置換後の旧判断にも本文のProposedが残った。一覧・MCPのstatusは管理情報を使うため、全文を読む場合と異なる説明になる。

`doctor`はこの不一致を指摘しなかった。文脈・判断・影響を記入した試験用3件では、不一致が残ったまま正常と表示した。

`--variant bare`を指定した別のaccepted記録では、frontmatterを持たず、本文のStatusがAcceptedとなる例を確認した。テンプレートやモードの調整余地はあるが、bareでのタグ・置換・更新を含む運用全体は未評価。全モード共通の不具合とは断定しない。

## 利点の解釈と費用

試験用要約は元Issueより短いが、これは担当者が判断を選び、要約した効果を含む。同じ要約を通常のMarkdownへ置いた場合との比較は行っておらず、短文化をadrs固有の成果とはしない。要約内容・状態・タグ・置換範囲の整備と、元Issue変更後の更新は別途必要になる。

初見の人の検索時間、AIの判断精度、長期の更新漏れ、作成・保守を含む総費用は測定していない。専用の評価モデルは追加起動していない。コマンドの実行成功を、導入効果や内容の正しさの証明にはしない。
