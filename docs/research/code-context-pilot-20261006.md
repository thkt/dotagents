# コードの書き方を既存の検査へ接続する限定試行

公開時の補足（2026-10-20）：以下は10月6日の観測です。当時のコード・設定は[確認基点の固定版](https://github.com/thkt/dotagents/tree/918aa6ec5a582da43a82bf831240c2f921f6d686)で確認できます。現在の適用範囲と実行手順は[開発方針](../wiki/development-policy.md#集計で蓄積値を毎回コピーしない)へ反映しました。現行lintは`scripts/`と`eval/`を対象にします。今回の公開で、実モデルによる改善効果を再検証したものではありません。

「`reduce`で大きくなる蓄積値を毎回コピーしない」という既存規則を選び、理由・適用境界・使う入口を文書へ接続しました。既存lintと制御テストで正例、違反例、適用外を確認できたため、新しいルール・テスト・実行基盤は追加していません。

記録日は2026-10-06、dotagentsの確認基点は `918aa6ec5a582da43a82bf831240c2f921f6d686` です。対象は未コミットの文書差分を含むローカル作業ツリーです。問いは、[コンテキスト分類の設計案](product-context-representation.md)に沿って、1件の既存規則を見つけ、適した媒体へ残し、開発で使う入口と検証・見直しをつなげられるか、です。AI開発への改善効果を測る試行ではありません。

## 規則を選んだ理由と通常の利用場面

[AGENTS](../../AGENTS.md)から[開発方針](../wiki/development-policy.md#typescriptの書き方)へ進み、lint設定、実装、既存テストを確認しました。型検査と書式設定も先に確認し、それらと役割が異なる集計処理の規則を選びました。

実コードの `scripts/implement/review.ts` の `parseReview` は、新しいレビュー指摘をローカルの配列へ追加しています。`scripts/implement/run-report.ts` の `actorLogGroup` は、イベント行を`flatMap`で表示項目へ変換し、読取失敗時の警告を配列へ追加します。こうした通常の集計処理を変更するときに、出力を維持しながら不要な蓄積値コピーを避ける知識が必要です。既存コードで違反や性能問題を発見したという意味ではありません。

結果の値を確認するテストだけでは、毎回の配列コピーを見つけられない場合があります。一方、lintの成功だけでは理由や変更してよい範囲が分かりません。この分担を具体化するため、今回は理由と境界を既存wikiへ補い、機械判定は既存lint、検出の維持確認は既存制御テストへ残しました。

## 既存の検出と3例の動作確認

既存の `scripts/tests/checks/codebase-checks.test.ts` は、一時repoへ現在の設定・ローカルプラグイン・型設定をコピーし、実際の`bun run lint`を呼びます。許容するローカル変更、各要素のコピー、文字列のconcat、変数の隠蔽などの対照を通します。unsafe assertionと蓄積値コピーの10違反は、診断名・対象ファイル・件数で確認します。構文や型の失敗をlintの検出と取り違えないよう、違反例も先に型検査します。

今回は次の既存テストを実行し、1件成功、失敗0件でした。他の4テストは名前で絞ったため対象外であり、未実行を成功には数えません。

```sh
bun test scripts/tests/checks/codebase-checks.test.ts --test-name-pattern 'lint rejects unsafe assertions'
```

さらに警告行の一覧を作る小さな処理を、製品コードから分離した一時repoで3通り書きました。現在の `package.json`、`.oxlintrc.json`、`tsconfig.json`、`scripts/lint/local/`をコピーし、既存依存を参照して、型検査・lint・Bunでの出力と入力非変更を確認しました。対象関数はすべて `readonly string[]` を受け取り、`string[]`を返します。

| 例 | 集計の書き方 | 型検査 | lint | 出力・入力非変更の確認 |
| --- | --- | --- | --- | --- |
| 正例 | 新規の`[]`へ`acc.push(message)`し、`acc`を返す | 成功 | 成功、診断0件 | 成功 |
| 違反例 | `acc.concat(message)`を毎回返す | 成功 | 失敗、`local(no-reduce-accumulator-copy)`のerror 1件 | 成功 |
| 適用外 | 項目オブジェクトだけをspreadでコピーし、その値を新規配列へ追加する | 成功 | 成功、診断0件 | 成功 |

共通入力は文字列2件で、3例とも同じ順序と値の一覧を返しました。違反例を正例へ書き換えると、出力と入力非変更を保ったままlintを通せます。この観測は、機能上同じ結果でも規則違反を区別することと、各要素のコピーまで禁止しないことを確認したものです。実際の速度やメモリ削減は測っていません。

再確認は上記の既存テストを使います。3例を再現する場合は、同じコピー元とツール版を使った一時repoに、関数の引数を`messages: readonly string[]`、返値を`string[]`として表の実装を置きます。入力を `['版が違う', '入力が欠けた']` とし、型検査、`bun run lint --format json`の終了値・診断名、実行結果と元の入力を確認します。適用外の例は`messages.map((message) => ({ message }))`を入力項目に変換してから集計します。期待する結果を緩めたりlintをdisableしたりして成功へ変えません。

## 確認できたこととまだ測っていない効果

必要性は、指摘や警告を集計する実コードと、同じ機能結果でもコピー操作を区別する3例で説明できます。ただし、今回の開発で過剰なコピーによる障害が発生していたわけではありません。

到達性は、今回の担当が既存の入口と検索から理由・設定・実装・テストへ進めた範囲で確認しました。新しい担当AIが自力で見つけられるか、入口の追記が到達率を変えるかは比較していません。

効果として確認したのは、既存検査が対象の違反を拒否し、対照を通すことです。今回の追記によるAIの遵守、レビュー品質、手戻り、時間・使用量の改善は未検証です。実モデルは呼び出していません。所有権や副作用、未知の値・呼出し形の検出、実際の性能もこの検査だけでは保証しません。
