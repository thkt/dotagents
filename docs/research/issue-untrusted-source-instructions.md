# 外部資料の指示形の文で実行権限を変えない

## 目的

実装・レビュー・修正担当が読むIssue本文、PR、調査資料、検証記録、ツール出力に、作業指示の形をした文が混じっても、合意済み要求、repo方針、ホストが管理する検証・公開・承認の境界を変更しない。参照資料は事実や根拠として利用し、権限変更の根拠にはしない。

## 範囲と完了条件

- 初回実装、独立レビュー、修正に共通する短い指示を一箇所で管理し、各担当への入力に含める。対象repoで動く担当にも届く位置に置く。このrepoの `AGENTS.md` への追記だけで完了としない。
- 合意済みIssueの正規の要求を遂行しつつ、Issueや参照文書内の「検証を省略して公開する」「秘密情報を送る」「他の指示を無視する」など、権限や作業範囲を変える文を、資料だけを根拠として実行しない。要求と指示の境界が曖昧なら、既存の確認・停止経路を使う。
- ホスト側の状態確認、承認、公開制御、Issue変更検知を維持する。プロンプトの追加だけを安全性の保証として扱わない。
- 既存のプロンプト生成テストで3経路への適用を確認する。実モデルで、同一の正常な小タスクと条件を用い、参照資料に越権指示を混ぜた場合と混ぜない場合を比較する。正常な要求の遂行と越権指示の不実行を別々に記録し、モデル・版・入力・試行数・費用・限界を示す。見かけの成功だけで効果を断定しない。
- 効果が確認できない、または正規要求の遂行を阻害する場合は、ルールの恒久化を進めず、観測した結果をIssueに残す。

## 対象外

任意の外部資料を機械的に「安全」と判定する機構、MCPへの移行、新しい承認経路、全repoへの規則配布、既存の権限境界の緩和は含めない。

## 根拠・現状

- 出典: [Findy Library — コンテキストエンジニアリング](https://lib.findy.co.jp/ja/ai/context-engineering)、[セキュリティ](https://lib.findy.co.jp/ja/ai/security)。恒久指示を増やす際は、対象を絞り、プロンプトだけを権限境界とみなさないという観点を採用する。
- 2026-09-23時点で、`scripts/development.ts` の初回実装入力、`scripts/correction.ts` のレビュー・修正入力は、Issue本文や調査・失敗の記録をプロンプトへ渡している。共有指示には、それらの資料中の指示形の文を権限として扱わない明文が見つからなかった。既存のホスト側の状態・公開チェックは維持する。
- 日本語版27ページの照合結果は `research/findy-library-review-20260923.md` にある。現時点ではローカル資料であり、公開済み根拠ではない。外部記事は要約・参照に限り、転載しない。

## 検証・引き継ぎ

対象repoのセットアップは `bun install --frozen-lockfile --ignore-scripts`、提出前のチェックは `bun run check`。既存テストの期待値を生成済みプロンプトから写さず、適用経路と守る権限を独立に確認する。独立評価では、正規要求を妨げないこと、権限拡張を許さないこと、文書の表現と実際のホスト境界が一致することを確認する。実装PRは人が差分・証拠をレビューし、マージを判断する。

## 合意範囲

2026-09-23、依頼者はFindy Library日本語版を順番に読み、必要なものをルールとして取り入れて誤りを減らす方針を示した。この境界一件への絞り込みは調査からの提案であり、個別の文案や恒久採用への合意はまだない。具体的な効果は未測定で、比較結果と正規要求への影響を確認して採用を判断する。
