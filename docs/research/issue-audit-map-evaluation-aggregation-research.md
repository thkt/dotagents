# 調査: 接続図の評価観点をさらに集約する必要性と条件を確認する

## 調査の目的と監査の補正

ローカル構成図の全接続図に残る評価観点の直列表示を、さらに整理する必要があるか調べる。2ノードへの集約を採用済みとは扱わず、現状維持で足りる結論も認める。

確認日: 2026-09-24。`docs/workflow-map.html`の参照コード版は`7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`。データには六つの十分性観点`S16〜S21`と四つの独立評価観点`R07〜R10`がそれぞれ直列で残る。しかし「工程ごとに読む」表示では、既に六観点・四観点を一つずつの開閉枠へまとめ、検索から個別IDへ移動できる。

今回の初期監査は全接続データに注目し、通常表示の集約済みを十分に区別していなかった。[#106](https://github.com/thkt/dotagents/issues/106)の完了記録と現行表示コードを照合して補正する。既存の通常表示を再実装するIssueではない。

根拠となる観点は[十分性の判断](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/scoping/references/sufficiency.md#L3)と[四観点の独立評価](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/review.ts#L102)。後者は[一回の評価呼出し](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/correction.ts#L567)に含まれ、四回のモデル実行ではない。

## 調査範囲と前提

通常の開閉表示、工程別の接続図、全接続図で、それぞれ何を確認する必要があるかを既存資料と現行操作から確認する。対象は全接続データ・直列表示に残る候補に限る。

#106で採用した「新しい集約ノード、別の通常用データ、第三の表示モードを作らない」条件を維持する。本IssueではHTML本体や採用条件を変更せず、集約ノードやレンダラーを実装しない。現行HTML・旧下書き・画面証拠はローカルに保全し、公開repoへ追加しない。

## 完了条件

- [ ] 通常表示で解消済みの問題と、全接続図に残る具体的な読解・更新上の負担を区別する。観点ごとのID・根拠・接続を辿る用途も確認し、ノード数だけで不要と判断しない。
- [ ] 現状維持、既存表示・説明の調整、六観点・四観点を一つずつにする候補を比較する。元情報・旧IDへの参照維持、接続条件、検索、レンダラーやaliasの保守負担を示す。実装用の別データを先に作らない。
- [ ] 候補が#106の採用条件を変える必要があるか明示する。必要な場合は判断対象と影響を示し、追加合意前に変更しない。追加合意なしで現状維持・不要・保留の結論を記録して完了できる。
- [ ] 観点・停止条件・独立評価・人の判断を削らない。表示上の8ノード・8矢印減という計算を、実際の呼出数・検査数・時間の削減と扱わない。最終案の数は対象版と表示範囲を揃えて示す。

## 検証と成果

現行HTMLを読み、通常幅・390px幅で開閉表示、全接続図、ID検索と直接参照を確認する。静的なデータ読解と画面確認を区別し、未実施なら明記する。結論・比較条件・未確認事項を本Issueへ残し、原資料と日本語を確認する。読解・画面確認だけの調査に共通check・実モデル・公開試行を追加しない。リポジトリ文書を変更する場合は現在の文書方針と`bun run check`を適用する。

確認時の図のSHA-256は`9ff7de1d20c845922d5103fd3268cecd6c38d2b492ea51688a7aac88b5185407`。着手時に現在の内容と差分を再確認し、未追跡HTMLがGit HEADだけで取得できるとは扱わない。

## 関連Issueとの違い

[#106](https://github.com/thkt/dotagents/issues/106)で通常表示の集約と既存表示の維持は解決済み。本Issueはそれを未完了として再発行せず、全接続図へ追加整理を行う必要性と既存合意への影響だけを調べる。[#131](https://github.com/thkt/dotagents/issues/131)で行ったフェーズ順・参照版の一本化、特定の判断経路修正もやり直さない。新しいgate・台帳・モデル呼出しは対象外。
