# 既存PR修正の開始境界で重複する照合を減らす

## 目的と状態

PR #148で追加されたdraft運用を維持し、同じ工程内の不要な取得・照合を減らす。コード、手順、引き継ぎ、保守を合わせた最小化を目的とし、図の粒度を粗くして削減数を作らない。

2026-09-20、依頼者は調査で確認した2箇所の局所修正案と削減効果の報告を受け、「まずissueにする？」と指示した。その2箇所を実装範囲としてIssue化する。本体への適用は未実施で、今回はIssue公開まで。#128で合意したdraft公開・本文確認・ready切替・人の判断は変更しない。

調査版は[90a2e3ca95282f4a76fda750a1a5eaf1e017d360](https://github.com/thkt/dotagents/tree/90a2e3ca95282f4a76fda750a1a5eaf1e017d360)。追跡ファイルを隔離コピーし、外部応答を模擬する既存のdevelopment・revisionテストで候補を比較した。調査では実運用コード、現行HTML、GitHubの公開状態を変更していない。

## 隔離試験で確認した削減

既存PRがreadyで、媒体添付のない正常な修正1回を、同じfixtureで観測した。

| 項目 | 現行 | 候補 | 差 |
| --- | ---: | ---: | ---: |
| GitHub向けコマンド | 100 | 91 | −9 |
| Gitコマンド | 114 | 105 | −9 |
| runtimeの行数 | 基準 | 基準−1 | −1 |
| 詳細図のノード（候補は見込み） | 212 | 212 | 0 |
| 詳細図の矢印（候補は見込み） | 359 | 359 | 0 |

減った18回はすべて読取り。初回実装担当の起動後はコマンド列が一致し、draft化・push・本文更新・CI確認の回数と順序も変わらなかった。図の対象箇所は既存ノード内の細目であり、削除できる独立ノードはない。実装時に図の説明を合わせる場合も、ノード・矢印の削減実績には数えない。

Gitは一時repoで実行し、GitHub・モデル・独立評価は模擬応答。観測数には模擬された検証処理内部のコマンドを含まない。公開後の担当AIによるready切替は、この試験の対象外。実運用の待ち時間・障害率・課金の改善は測定していない。

- 現行の関連134テストと観測1件は135件成功。
- 候補では関連134テスト、観測1件、予約後の変化を注入する7件が、計142件成功。
- 追加の7件は、修正依頼・本文・branch・並行run・実効主体・push権限・Issueの変化を個別に注入し、意図した理由で停止すること、新しい実装担当と公開操作へ進まないこと、停止結果と既知URLを保持することを確認した。現行版でも7件とも成功。
- 最初の候補では対象照合を開始入力照合の後ろへ移したため、既存の1テストで停止理由が変わった。順序変更は不要と判断し、最終候補は元の検査順を維持した。

追加観測と不具合注入は調査用で、8件をそのまま常設テストへ追加する提案ではない。実装時は既存テストで不足する境界だけを残す。全体の`bun run check`、実モデル評価、別評価者による独立評価、実GitHubへの公開試行は未実施。

## 今回は削らない箇所

| 箇所 | 判断 |
| --- | --- |
| draft切替前後、push前後、本文更新前後、添付前 | 書込みでhead・本文・状態が変わる。切替前の対象・主体・権限・Issueの観測を使い回さない |
| 同じbranchを使うopen PRの照合 | 修正対象以外のPRにもpushが影響する条件を確認する。対象PRの照合だけでは代替できない |
| CI待機中と最終対象照合、ready直前と切替後の読戻し | 待機・担当AIの確認・外部書込みを越える境界。削除すれば現在の保証が変わる |
| 検証ラッパーとcorrection内部の修正対象照合 | 取得項目は似ているが、lock取得、保存state、active予約、戻り値・例外と停止記録の責務が異なる。この調査では安全に集約できることを実証していない |
| 新規publish内の実効主体の再取得 | PR検索後に主体が変わった場合を止める既存テストがある。削除だけでは検出条件を失う。取得順や責務の再設計は今回の小さな削減案へ混ぜない |

今回増えたdraft管理・ready切替の7ノードについて、同じ保証を維持して削除できるという根拠は得られなかった。すべての再照合が不可欠と証明したという意味ではない。
