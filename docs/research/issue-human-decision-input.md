## 目的と位置付け

優先度: 高。人が何を決めるべきか分からないまま依頼を受け取る往復を減らす。初回実装と追加修正が共有する既存の応答検査に限定する。#126のレビュー指摘IDや、レビューから人へ直接戻す契約の変更は含めない。

[parseRepairReply](https://github.com/thkt/dotagents/blob/0fec56c536763f8ccbd4bc4a9080c19beb14862d/scripts/repair.ts#L19)は `findings` が文字列なら空でも受理する。隔離試験で、`status: needs_human` と空文字または空白だけのfindingsが、いずれも有効な人の判断依頼として返ることを確認した。意味のある判断内容が入っている保証はない。

## 範囲と受入条件

- [ ] `needs_human` のfindingsが空または空白だけなら不正応答として扱い、有効な人の判断依頼として案内しない。既存の初回・追加修正それぞれの不正応答の停止経路へつなぐ。
- [ ] 不正応答でも生応答と作業差分・既存記録を保持し、空欄を推測で埋めない。再生成の自動試行、上限の変更、後続公開を追加しない。
- [ ] 内容がある正当な `needs_human` は、判断と影響を既存findingsから人へ渡し、回答が必要な作業を停止する。指示ファイル由来の判断依頼では、実際の出典と明示条件を示す既存の責任を維持する。
- [ ] 既存指示を照合し、問い・必要な選択・影響を既存欄で説明する責任へ集約する。文言や項目を重複追加せず、新しい応答項目・質問台帳・意味判定モデルを作らない。
- [ ] 通常の `repaired`、未知statusの診断保持、必要な対象照合を維持する。文字列の非空検査を判断内容の意味的な十分性の保証としない。

直接の入力境界で空文字・空白・正常な判断依頼を確認し、初回と追加修正の既存テストで停止・保全・後続抑止への接続を確認する。実モデルが必ず十分な判断材料を返すことや、実運用での発生頻度は未確認。既存の不正応答分岐を使うため、新しい工程・図のノードは不要。

## 検証と引き継ぎ

セットアップは `bun install --frozen-lockfile --ignore-scripts`。提出前は `bun run check`、差分の独立評価と人向け文書の日本語確認を行い、PRでは同じheadの `checks`・`verify` を確認する。人がレビュー・マージを判断する。既存テストを再利用し、今回の誤分類・後続抑止・保全に不足する検証だけを加える。プロダクト画面媒体は不要。

実装・テスト・文書の増減と、同じ範囲・粒度のノード・矢印の増減を既存のPR説明へ記す。原因調査や担当の選択が減る効果と、図の表示集約を分ける。全項目の純減はノルマにせず、行の圧縮や単なる移動を改善に数えない。新しい必須帳票・計測基盤は作らない。
