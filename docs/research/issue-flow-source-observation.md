## 2026-09-18 調査結果と実装案

以下は採用判断前に行った調査の結果。2箇所の共用を推奨し、その後、冒頭の採用決定により実装範囲として合意した。以下の試作の数値は本採用後の実測を示すものではない。

### 共用する範囲と残す境界

| 取得箇所と目的 | 間にある処理・変更可能性 | 判断 |
| --- | --- | --- |
| `verifyHost`開始時の全体snapshotと任意撮影のidentity | ignore照合のみ。capture/checkはまだ起動しない | 同じ取得結果から全体hashと撮影用hashを作る |
| capture実行後の`targetChange` | captureコマンドはcheckoutを書き換え得る | Issueと全体snapshotの再取得を残す |
| `installMedia`後の全体snapshotと撮影identity | 媒体の削除・コピー後。2つのhash取得間にはignore照合のみ | 媒体取り込み後に新しく取得し、その結果を共用する |
| check実行後の`targetChange` | checkコマンドはcheckoutを書き換え得る | Issueと全体snapshotの再取得を残す |
| `reviewTarget`のfilesと未追跡の本文・mode | 対象外のrun領域への記録と読取り専用のGit diff | ファイル本文を1回読み、hashと未追跡記録を同時に作る |

### 最小案・代替案

1. 既存の`sourceFiles`で名前・mode・hashを1回取得する。撮影用の除外はその配列へ適用する。通常のMarkdown・所定の記録の除外、直接指定した撮影定義・実行属性・symlink・媒体の扱いとignore照合を維持する。
2. レビュー資料を作る場合だけ、追跡ファイルと未追跡ファイルの一覧を既存のGitコマンドで別々に得て、集合を合わせて各ファイルを1回読む。未追跡ファイルだけ、その同じ本文からbase64またはsymlink先文字列を作る。全ファイルの本文保持、永続キャッシュ、無効化管理、新ライブラリ、新CLIは追加しない。

### 実装の受入条件と検証

- 安定した入力では、全体source hash・撮影identity・review targetId、および未追跡記録のpath/mode/symlink/contentを現行と一致させる。通常ファイルはbase64、symlinkはリンク先文字列として記録し、リンク先本文を代用しない。tracked/untrackedの移動だけで全体source hashを変えない。
- 追加・削除・内容・実行属性・symlink先・撮影定義・媒体の変更を引き続き検出する。任意撮影で除外できる記録と通常Markdownの変更だけは、従来の条件で再撮影を省ける。required設定や設定自体の変更、ignoredな撮影定義・媒体に関する現行の拒否条件を維持する。
- 各処理の取得結果はその境界内で消費し、capture/check/モデル/媒体コピーをまたいで再利用しない。レビュー資料作成後にもIssueと全体snapshotを再取得してからモデルを起動し、終了後も再取得する。
- 既に消えている追跡ファイルは現行どおり削除として扱う。`lstat`後の消失・読取りエラーや、レビュー用に列挙済みの未追跡ファイルの消失は、部分的な記録を成功扱いせず停止する。作成途中の記録はモデル起動の許可にしない。
- checkで確認した対象から、レビュー資料作成中に追加・内容・mode・symlinkの変更が生じ、最終照合でもその差分が残る場合は、source不一致としてモデルを起動しない。同じ読取りから本文とhashを生成する。一方、走査中の変更と復元を完全に捉える保証や、全ファイルを同時点で読む保証は現行にもなく、今回の範囲では追加しない。
- 既存の[撮影再利用・属性・定義の検証](https://github.com/thkt/dotagents/blob/e550b197c929e3608b6744f4104ebb28fe3720a1/scripts/tests/correction-capture.test.ts#L181)、[削除・rename後のstage/commitの検証](https://github.com/thkt/dotagents/blob/e550b197c929e3608b6744f4104ebb28fe3720a1/scripts/tests/correction.test.ts#L20)、[レビュー対象・記録の検証](https://github.com/thkt/dotagents/blob/e550b197c929e3608b6744f4104ebb28fe3720a1/scripts/tests/review.test.ts#L321)を再利用する。レビュー記録の既存fixtureで本文・symlink・modeとhashの一致を確かめ、取得途中の消失と資料作成からモデル起動までの変更検出に不足があれば、その不具合だけを再現する。呼び出し順や補助関数の形を固定するテストは追加しない。

今回の試作では、安定入力の全体hash・撮影hash・targetId・diff・未追跡記録の一致、6種類の変更後のhash一致、`lstat`後の消失、列挙した未追跡の消失の拒否を確認した。本番フローへ接続した検証、全体の`bun run check`、独立評価、実モデル・実商品での試行、経過時間・メモリーの測定は未実施。採用後は実装差分に対する`bun run check`と既存の独立評価を経てPRへ引き継ぐ。
