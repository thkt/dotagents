# 修正担当の反証と変更しない理由を次の独立評価へ渡す

## 目的と現在の根拠

修正担当が調べた反証や変更しない理由を次の独立評価へ明示的に渡し、同じ指摘を新しい根拠なしに評価し直す負担を減らす。修正担当の判断だけで指摘を解消済みにしない。

監査版はmain `7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`。現在は[修正応答のfindingsをstateへ保存](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/correction.ts#L664-L673)するが、[次のcheckでfindingsを更新](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/correction.ts#L462-L474)し、[review入力](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/correction.ts#L566-L573)には直前のレビューを渡す一方、修正応答やその参照を明示していない。

既存のcorrection fixtureで、check成功、同じ文書指摘の反復、成果物を変更せず理由を返す修正を模擬した。有限の試験設定でcheck 3回・review 3回・repair 2回が同じsourceに対して実行され、修正理由を識別する文字列は次のreview promptに含まれなかった。これは入力の観測であり、実モデルが根拠を発見できないことや改善後の収束を証明するものではない。

## 範囲・対象外

追加修正から次の独立評価への受け渡しを対象とする。既存の修正応答・記録を使い、反証、変更内容、変更しない理由を、どの修正・成果物に対する説明か分かる形で渡す。既存の指摘履歴と現在の成果物を評価する責任は独立評価担当に残す。

checkの再利用・省略、修正回数やモデル時間の上限復活、新しい評価工程・専用AI・台帳、過去runの変換・再開は対象外。初回評価に修正記録の存在を要求しない。

## 受入条件

- [ ] 直前に正常終了した追加修正の説明と根拠を、次の独立評価から明示的に辿れる。別runや古い修正の理由を今回の根拠として取り違えない。
- [ ] 独立評価担当が修正説明を現在のIssue・成果物・検証結果と照合する。修正担当の自己申告をacceptedやfixedへ自動変換しない。
- [ ] 成果物を変更した修正と、反証に基づく無変更の修正を扱い、必須指摘の全件再判断、対象ID照合、現在のcheck・独立評価・停止・保全条件を維持する。
- [ ] 不正応答・needs_human・修正失敗では従来どおり停止し、評価への受け渡しを理由に続行しない。説明の二重保存や新しい必須入力を増やさない。

## 検証・関連・合意

既存のcorrection/reviewテストを使い、修正あり・無変更の反証・修正記録なしの初回・不正応答・別の修正記録の混入を確認する。模擬テストでは受け渡しと制御を確認し、実モデルによる指摘解消率・費用の改善は未確認として分ける。

セットアップは`bun install --frozen-lockfile --ignore-scripts`。実装提出前に`bun run check`と差分の独立評価を行い、日本語を確認する。PR公開時に同じheadの`checks`・`verify`を確認する。対象設定のcaptureは`null`で、画像・動画は不要。人の要求判断・レビュー・マージを維持する。

完了済みの[#82](https://github.com/thkt/dotagents/issues/82)は過去レビュー指摘の保持、[#99](https://github.com/thkt/dotagents/issues/99)は実装・修正の共通指示と応答検査、[#155](https://github.com/thkt/dotagents/issues/155)は通常runの回数上限撤廃を扱った。今回は残っている修正理由の受け渡しだけを扱い、それらの完了範囲を再実装しない。成功checkの再利用条件は別の調査Issueで扱う。

必要な根拠は本Issueと固定版リンクで足り、追加の必須調査報告や未commitの下書きを後続作業の入力にしない。着手時に最新の採用版で適用性を確認し直す。
