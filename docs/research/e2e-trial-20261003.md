# e2eの限定比較（2026年10月3日）

公開時の補足（2026-10-20）：以下の結論・未確認事項・公開状態は10月3日時点の記録です。その後、[PR #381](https://github.com/thkt/dotagents/pull/381)で対象repoへの条件付き採用の手順が追加されています。現在の採用条件は[実装・検証の手順](../../skills/implement/references/testing.md#対象repoでのe2eの条件付き採用)を参照してください。今回、新しいモデル試行は行っていません。

## 結論

対象アプリのUI操作に限定して試す価値を確認しました。商品検索アプリの3ケースでは、Playwright、e2eのコード操作、e2eのAI操作がすべて正常系を通過し、注入した3種類の不具合を検出しました。健全なボタン名変更では、固定ロケーターのPlaywrightは失敗し、AI操作は新しいボタンを見つけて成功しました。

共通ハーネスへの採用は提案段階です。キャッシュ再生した操作の成功は、要求達成の保証になりません。結果のコード検証を残し、選択したテストの未実行を拒否する確認も必要です。既存のcheck・撮影基盤・設定・スキルは変更していません。commit・push・Issue・PR作成も行っていません。

## 対象と比較条件

依頼は、[tester.army/e2e](https://tester.army/e2e)の導入価値を実行して確認することです。AI操作には、ユーザーが選択・認証したChatGPTログインを使いました。認証情報はe2eの保存先にあり、調査資料には含めていません。

対象は[dotagents-workflow-trialのcommit d0134086](https://github.com/thkt/dotagents-workflow-trial/tree/d0134086ad9bdddb5ed2693327cb1ffb0859c4a2/trial)にある架空の商品一覧です。`trial/public`と`trial/server.js`を一時領域へコピーしました。元のcheckoutは編集していません。

| 条件 | 固定した内容 |
| --- | --- |
| 実行環境 | macOS arm64、Node 26.10.0、Bun 1.4.2 |
| パッケージ | e2e 0.15.2、@e2e-dev/web 0.11.1、Playwright 1.63.0、ai 7.0.127、@ai-sdk/openai 4.0.83 |
| ブラウザー | Chromium、1280×800、各テストで新しいcontext |
| モデル | chatgpt.responses/gpt-6-luna、推論設定はprovider既定。利用可能モデル一覧では既定medium |
| 上限 | worker 1、再試行0、テスト45秒、expect 2秒、AI操作ごとに最大5モデル呼び出し・8操作 |
| 結果の確認 | 商品名の順序、表示件数、検索欄の値、再読込み後の並び順をコードのexpectで確認 |
| 記録 | traceを保存。テレメトリーは無効化。AI traceは私的な一時領域に保存 |

e2eのactionTimeoutは5秒です。Playwrightの操作待機は個別指定せずテスト期限に従うため、ボタン名変更時の待機時間は同条件ではありません。正常系の速度は各runnerが報告した時間で比較し、Node起動・導入・認証・資料作成の時間を含めません。

試行は各条件1回です。正常系のAI初回と再生は別条件とし、同じ試行の再試行に数えません。不具合・ボタン名変更・厳格モードの各条件を始める前に、正常系で得た同じキャッシュへ戻しました。モデル呼び出しがある条件の入力は、それぞれの画面と操作指示です。判定用の不具合名や期待値一覧をモデルの指示へ渡していません。

## 実行結果

### 正常系とキャッシュ再生

| 実行方法 | 正常系 | runnerの時間 | モデル呼び出し | 記録されたトークン |
| --- | --- | ---: | ---: | ---: |
| Playwrightのコード操作 | 3/3成功 | 1.064秒 | 0 | 0 |
| e2eのコード操作 | 3/3成功 | 1.036秒 | 0 | 0 |
| e2eのAI操作・初回 | 3/3成功 | 22.548秒 | 6 | 25,687 |
| e2eのAI操作・キャッシュ再生 | 3/3成功 | 1.286秒 | 0 | 0 |

3ケースは、ノートの検索、降順と検索該当なしからのクリア、降順選択と再読込みです。AI版では、検索入力・クリアボタン操作・降順選択の各1操作を自然言語へ置き換え、準備と期待値はコード版と揃えました。

キャッシュ再生によるモデル呼び出しの削減は確認できました。再生後の速度は今回のPlaywrightとほぼ同程度です。安定した単純な操作を置き換えるだけで、速度が改善するとは判断しません。

### 不具合注入

| 注入した不具合 | Playwright | e2eのコード操作 | e2eのAI操作 |
| --- | --- | --- | --- |
| 検索時に全商品を表示したままにする | 表示商品名の不一致を検出 | 同左 | 同左。操作の再生自体は成功扱い |
| クリアボタンの処理を無効化する | 検索欄の値の不一致を検出 | 同左 | 再生後にAIへ引継ぎ、ボタンが機能しないと判断して失敗 |
| 並び順のlocalStorage保存を無効化する | 再読込み後の値の不一致を検出 | 同左 | 同左。操作の再生自体は成功扱い |

3種類とも、対象の誤動作を理由に失敗しました。ブラウザー起動やモデル接続などの実行不能を検出成功へ数えていません。AI版のクリア失敗はモデル呼び出し3回・13,115トークン・27.875秒を要しました。別の入力操作で検索を解除する回避は、この試行では観測しませんでした。別モデル・指示でも同じ判断になる保証はありません。

検索不具合では、AI操作ステップに過去の「2件に絞り込まれた」という説明が再掲され、ステップのstatusはpassedでした。実際は4商品が表示され、後続の`expect(...).toHaveText(...)`が失敗しました。並び順の保存不具合も、再生後の画面だけでは見つからず、再読込みと値の検証で検出しました。操作の再生成功や記録済みの説明だけを受入根拠にしないことが必要です。

### 健全なUI変更と未実行

クリアボタンの表示を「検索をクリア」から「入力をリセット」へ変え、動作は維持しました。固定ロケーターのPlaywrightは該当ボタンを見つけられず失敗しました。e2eのAI操作は古い操作対象を見つけられず、ライブ操作で新しいボタンを押して成功しました。モデル呼び出し2回・8,590トークンです。`--strict-cache`では`REPLAY_STALE`と`target-not-found`で終了2となり、モデルは呼び出されませんでした。

この差はUI変更への追従の具体例です。ただし、安定したtest idを使うPlaywrightとの比較、実際のテスト修正時間、長期的な保守費用は測定していません。

選択したテストがすべてskipの場合は`NO_TESTS`で終了2となり、reportは生成されませんでした。一方、1件成功・1件skipを選択した場合は終了0でした。レポートには選択対象外のテストも`filtered`のskipとして入ります。共通ハーネスへ接続するなら、終了コードやskip総数だけで判定せず、選択した対象の実行完了・失敗・flaky・未実行を照合する必要があります。既存のPlaywrightレポート用判定器との互換性は、実接続していません。

## 記録、再現方法、失敗の扱い

[抽出結果JSON](e2e-trial-20261003.json)に、版、設定・テスト・実行スクリプトの本文とSHA-256、レポートのSHA-256、選択した対象、操作記録、モデル使用量、不具合の失敗理由を保存しました。失敗ケースを含むAIの合計は11呼び出し・47,392トークンです。トークンはproviderが返した入力と出力の記録で、キャッシュ入力は入力の内数です。請求額・アカウントの残量は測定していません。

私的な一時領域には元のレポート、ログ、AI trace、キャッシュ、画像とPlaywright traceが残ります。e2eがreportに列挙した32個の成果物について、ファイルの存在とSHA-256一致を確認しました。これは記録の整合確認であり、全画像・traceを人が閲覧した確認ではありません。一時領域の恒久保存は保証しません。公開可能なJSONには生の絶対パスを置かず、取得した必要な結果と入力を残しています。

再現用の新しい作業rootを用意し、上記commitの`trial/public`を`app/public`へ、`trial/server.js`を`app/server.js`へコピーします。JSONの`inputs`を作業rootからの同名パスへ取り出し、`tests/`と`evidence/`も用意します。保存スクリプトはこの配置を前提にします。記載のパッケージ版を作業rootへ導入し、Chromiumとe2e側のChatGPT認証を準備します。サーバーは別の端末で作業rootから`PORT=4187 bun app/server.js`として起動します。コード版を実行後、AI版をキャッシュなしの初回、同じキャッシュでの再生の順に実行します。次のコマンドも作業rootから実行し、各runは別のoutputへ保存します。

```sh
E2E_TELEMETRY_DISABLED=1 ./node_modules/.bin/e2e run tests/deterministic.e2e.ts --output evidence/e2e-normal
E2E_TELEMETRY_DISABLED=1 ./node_modules/.bin/e2e run tests/agent.e2e.ts --output evidence/ai-cold --ai-trace
E2E_TELEMETRY_DISABLED=1 ./node_modules/.bin/e2e run tests/agent.e2e.ts --output evidence/ai-warm --ai-trace
```

不具合注入は`run-mutations.py`の定義を使います。正常系の初回・再生を完了した後に`run-mutations.py`、選択式を修正した`run-pw-mutations.py`、`run-ai-mutations.py`の順に実行します。前のスクリプトが`evidence/`へ保存する変異ソースをAI版も使用します。AI版は正常系の`replay-cache`から`evidence/cache-baseline`を初めて作るため、この保存先がまだない作業領域を使います。Playwrightで最初に行った3つの不具合試行は、タイトルを選ぶ正規表現が不適切で`No tests found`になりました。これは比較手順の誤りで、検出の根拠にしていません。選択式を修正した`run-pw-mutations.py`の3試行を採用し、初回のログも保全しました。

最新パッケージの導入はホストのnpmにある、公開から一定期間待つ設定で一度失敗したため、一時領域でのinstallに限り`--min-release-age=0`を指定しました。グローバル設定は変更していません。ChatGPTのデバイス認証は、ユーザーが完了画面を確認した後もCLIが待機したため中止しました。通常のブラウザー認証は成功しました。デバイス認証の不一致の原因は未確認です。

## 採用候補と未確認事項

採用するなら、UI変更への追従が必要な対象アプリの数フローへ限定し、AIは操作に使い、重要な結果・副作用・永続化はコードで検証する構成を勧めます。合意した操作経路自体を守るケースでは、固定ロケーターや厳格なキャッシュ判定を選びます。モデル使用量・引継ぎ理由・失敗記録を残し、終了0だけで受け入れません。

現時点では採用判断の材料を得た限定試行です。複雑な業務画面、mobile、複数ブラウザー、実CI、撮影アダプター、fork PR、機密データを扱う画面は未検証です。AI判断の反復による安定性、保守時間、初期導入費用を含む総費用、依存更新時の互換性、独立評価も未確認です。共通基盤を置き換える根拠はありません。
