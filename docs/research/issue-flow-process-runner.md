## 目的と現状

CIや公開などの利用側が、修正・知識・評価のフロー全体へ依存せず、共通の実行処理を使えるようにする。

[scripts/correction.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/correction.ts#L41) にcommand・プロセスグループ・割込み状態があり、[scripts/publish.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/publish.ts#L7)、CI、target、試行CLIが参照する。また [scripts/input.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/input.ts#L2) と [scripts/review.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/review.ts#L2) は互いに実行時importを持つ。

## 範囲と完了条件

- [ ] command・子プロセス停止・中断処理を小さな共通モジュールへ集め、公開・CI・対象解決などがcorrectionを読む依存を除く。
- [ ] activeGroupなど実行管理の所有者を一つに保つ。複数モジュールへの複製や、未対応のコマンド並列化を導入しない。
- [ ] 基本的な値の判定と保存済みレビューの検査を整理し、inputとreviewの実行時importの循環をなくす。型・意味の検査を削って解消しない。
- [ ] プロセスグループの終了、中断・タイムアウト・出力保存の振る舞いと、修正予約を起動前に残す責任を維持する。
- [ ] 共通処理から上位フローへ戻る依存がなく、利用側の依存範囲が縮んだことを示す。汎用実行エンジン、新しい状態形式、全体のファイル分割は対象外。

## 重点的な検証・順序

小さな終端・handoff・CIの改修後を推奨。初回実装と修正の共通化に先行させると責務を分けやすいが、処理を共通化すること自体は本Issueへ含めない。

`correction-process.test.ts` とpublish／CI／target／actorの既存テストを再利用する。呼出元を越えて中断と子プロセス停止が届くこと、既存の出力・停止結果を維持することを確認する。行数やファイル数の減少を完了条件にしない。
