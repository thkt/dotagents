## 目的と現状

PRの読み手が未完了の作業と担当を一度で把握できるようにする。

[scripts/review.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/review.ts#L245) は公開・CI・媒体確認・人のレビューをAIのhandoffへ記載させる。一方、[scripts/pr-body.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/pr-body.ts#L62) も定型作業を追加してからhandoffを展開するため、同じ作業を二重に記載し得る。公開済みPRごとの重複量は未集計。

## 範囲と完了条件

- [ ] 公開・CI・必要な媒体確認・人のレビューなど、実行条件から決まる定型作業はホスト側で一度だけ組み立てる。
- [ ] AIのhandoffはIssue固有の未確認事項・必要な対応・担当へ絞る。独立評価の指示とPR生成を揃え、定型文の出力を二重に要求しない。
- [ ] 未確認事項と担当を保持し、ローカルcheck・独立評価・CI・媒体の実表示確認・人の判断を互いの完了へ読み替えない。判断を妨げる未解決事項はaccepted後の残作業へ追い出さない。
- [ ] 条件が異なる自由文を類似文字列で削除しない。対象範囲内の空の節・同じ但し書きは、必要な説明を一箇所に残して整理する。
- [ ] 内部の指摘履歴・生ログは保全し、ホスト内のパスや生ログを公開本文へ混入させない。

## 重点的な検証・順序

終端照合の削減後の小さな改修候補。[#69](https://github.com/thkt/dotagents/issues/69)の担当分担を維持する後続改善。

既存の `review.test.ts`・`development.test.ts` で、媒体あり／なしとIssue固有のhandoffを含む本文を確認する。同じ定型作業が二重の生成経路を持たず、固有の条件・担当や公開情報の保護を失わないことを確かめる。実際のAI応答で重複が完全になくなるとの保証はしない。

## 検証と引き継ぎ

セットアップは `bun install --frozen-lockfile --ignore-scripts`、提出前は引数なしの `bun run check`。既存の関連テストを再利用し、不足する現実的な失敗条件だけを追加・更新する。独立評価と同じPR headの `checks`・`verify` を確認し、人がレビュー・マージを判断する。模擬コマンドの検証、実モデル、実際の公開は別の証拠として報告する。

プロダクト画面媒体は不要。必要な共有根拠はIssueまたは `research/`、内部ログは既存のcheckout外保存先へ置く。既存のrun・失敗記録・他作業の差分を削除・変換せず、新しい必須台帳を作らない。対象・権限・版の照合と、要求変更を人へ戻す責任を維持する。

## コードとフローの削減評価

2026-09-18、依頼者の追加指示を反映。従来の動作要件と、実装／調査・設計の区分を維持する。

- [ ] 追加の前に削除・一本化で解決する案を検討し、置き換えた旧処理・重複する指示・不要な受け渡しを残さない。テストも既存の検出力と重複する準備・ケースを整理する。
- [ ] 着手版と成果物を比べ、実装・テスト・文書の行数増減と、対象フローのノード・矢印の増減を既存のIssue／PRへ短く記す。実際の操作・判断・受け渡しと図の表示集約を分け、同じ対象範囲・粒度で比較する。調査Issueは案の比較までとし、推定と実測を区別する。
- [ ] 単なるファイル移動や行の圧縮を削減効果に数えない。削減なし・増加も明記し、増えるコードが減らす手順・分岐・受け渡しと保守負担を比較する。全項目の純減をノルマにせず、新しい測定基盤・必須帳票は作らない。
- [ ] 必要な異常検出、対象・権限の照合、独立評価、人の判断を維持する。検査やテストの統合・削除は、どの現実的な不具合を残る検証で検出するか説明する。変更を挟む再照合を単なる重複としない。

### このIssueで狙う削減

- 定型handoffをモデルへ要求する指示と、PR生成側の重複文・空節のための分岐を見直し、指示・本文生成コード・同じ保証のテストを減らす。自由文を比較する新しい重複除去器は追加しない。
