# scopingの参照分離と読み分けの試行

## 問いと対象

scoping Skillの共通判断と、実験・UI・ロジック・保存・Issue公開に固有の手順を分けたとき、必要な参照を選べるかを確認した。[参照を分けるという着想](https://zenn.dev/koinunopochi/articles/17a2a89688254b)を、このリポジトリの既存の正本と権限境界に合わせて試した。これは採用効果の確定ではなく、2026-09-23時点の局所的な検証記録である。

比較元は公開リポジトリのHEAD `16d70c23918d69d4dbc01795ac1a886938ee573d`。候補は `skills/scoping/SKILL.md` と参照5件（`sufficiency.md`、`session.md`、新規の `experiment.md`、`ui-context.md`、`logic-context.md`）だけを比較元へ重ねた。`implement` Skillと既存の `issue.md` は比較条件で変更していない。ローカルの他の未commit資料、会話履歴、個人メモリは渡していない。

## 方法と結果

Codex CLI 0.156.1、`gpt-6-astra`、reasoning effort `high`、ユーザー設定なし、ephemeral・read-onlyで、合成した二つの依頼を各条件で1回実行した。単純ケースはREADMEのリンク修正について公開しないIssue下書きを整理する依頼。不確実ケースはジョブ中断後に完了通知が届く状況で、何を観測し人へ返すかを決める依頼。事前に、必要な参照の選択、要求と検証の具体化、観測と未許可の外部書込みの区別を確認点とした。どの試行もファイル変更・GitHub公開は行っていない。

| ケース・条件 | 実際に読んだscoping参照 | 確認結果 | 入力token（うちcache）/出力token |
| --- | --- | --- | --- |
| 単純・HEAD | `sufficiency.md` | 下書きの要求と検証を整理。不要な固有参照は読まず | 61,162（41,728）/785 |
| 単純・候補初版 | `sufficiency.md`、`session.md`、`issue.md` | 内容は満たしたが、保存と公開の参照も読んだ | 103,280（80,128）/1,014 |
| 単純・候補改訂版 | `sufficiency.md` | 保存・公開・実験・UI・ロジックの参照を読まず、下書きを整理 | 87,267（70,272）/982 |
| 不確実・HEAD | `sufficiency.md` | 通知順序の可能性を区別し、外部書込みを保留 | 52,715（44,416）/836 |
| 不確実・候補改訂版 | `sufficiency.md`、`experiment.md`、`logic-context.md` | 区別できる観測を先に示し、未許可の外部書込みを保留 | 101,311（80,384）/1,111 |

初版の過読を受け、候補のSkill本文で `session.md` と `issue.md` を読む条件を明示した。改訂版は二つの依頼で想定した参照選択と判断を満たした。ただし、両ケースとも改訂版の総入力・出力tokenはHEADより多い。リポジトリ文書の追加読込みや反復を含む総量であり、参照分離による費用削減は確認できない。請求費用は測っていない。

二つの合成依頼・各1回だけで、Skillの自動選択、実際の要求整理からIssue反映まで、他のモデルや依頼の再現性は未確認。次に採用効果を判断するなら、実務に近い同一依頼で参照選択の正確さ、要求・失敗条件の充足、読込み量と費用を分けて比較する。現段階では参照の条件付き配置を局所的に確認した結果として扱う。
