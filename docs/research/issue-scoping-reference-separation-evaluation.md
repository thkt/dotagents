# scopingの参照分離を実務ケースで検証し採否を決める

## 目的と根拠

scoping Skillの共通判断と、実験・UI・ロジック・報告保存・Issue公開に固有の参照を分ける候補について、実務で必要な資料を選び、要求・失敗条件・合意・権限の確認を保てるか評価して採否を決める。参照を分けたという構造やtoken削減を、先に成功条件としない。

2026-09-23のローカル試行は、公開版`16d70c23918d69d4dbc01795ac1a886938ee573d`と、scoping Skill・参照だけを変更した候補を比較した。`gpt-6-astra`、reasoning effort high、ユーザー設定なしのread-only条件で、合成した二つの依頼を各条件一回実行した。初版は単純な下書きでも保存・公開用参照を読んだため、候補の読む条件を改訂した。改訂版は両ケースで想定した参照を選び、要求と未許可の外部書込みの区別も保った。一方、総入力tokenは単純ケースで現行61,162→改訂版87,267、不確実ケースで52,715→101,311、出力tokenもそれぞれ785→982、836→1,111へ増えた。請求費用、実際の要求整理からIssue反映まで、他の依頼・モデルでの再現性は測っていない。

候補の変更は現在ローカルの未commitファイルに残る。比較元も現在のmainより古い。未commit資料を採用済みのSkillや公開された根拠と扱わない。確認したmainは`7369b8cf3208ebefe7b4dc0f82be3830eea8b9f7`（2026-09-24）。着手時に実際のmainと候補の差分を取り直す。

## 範囲

採用済みのscoping Skillと、今回の参照分離候補だけを対象にする。関係ないローカル変更・会話履歴・個人メモリを比較入力へ混ぜない。`implement` Skill、runtime、Issue公開権限、既存の人の判断・独立評価の責任を変更しない。

特に、候補では元のSkill本文にある要求と合意の整合確認の一部を`session.md`へ移した一方、その参照は報告が必要な場合に限定した。`sufficiency.md`にも整合確認が残るため、下書き経路で確認漏れが生じると断定せず、必要な観点へ到達できるか確かめる。

比較方法にも制約がある。main `7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae` の[`skill-eval.ts`](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/skill-eval.ts#L26)は、`instructionFiles`をbefore/after両commitから通常ファイルとして読み込む。候補で追加した参照をそのまま比較入力に渡せない静的制約があった。最新の入口を再確認し、必要な比較を汚染せず行う方法を決める。この制約だけを理由に汎用eval基盤を拡張しない。

## 完了条件

- [ ] 最新mainと候補の関係する差分、既存の合意・正本・旧参照を確認する。候補に含まれる別用途の未commit差分を区別する。
- [ ] 「短い下書き」「再利用する調査報告」「Issue公開・更新」を扱い、それぞれで読むべき参照、読まなくてよい参照、要求・失敗条件・根拠・合意・権限の確認を明示する。参照を読まないことや文字数だけで良否を決めない。
- [ ] 保存済み試行と静的な経路確認で採否を決められるか判断する。不足する場合だけ、同じ依頼・モデル・入力設定で実務に近い小さな比較を行い、要求充足・不要な読込み・時間・使用量・費用の測定値と未測定値を分ける。新規参照を共通入力から比較元にも読ませるなど、対照条件を変えない。
- [ ] 比較に新規ファイルが必要な場合、現在のeval入口で扱えるか確認し、扱えないなら今回の比較に必要な最小の方法を選ぶ。ツール変更が必要なら、それ自体の適用範囲と検証条件を明らかにしてから判断する。
- [ ] 採用・修正・見送りの結論と根拠を本Issueへ残す。採用する場合は、変更するSkill・参照、維持する経路と権限境界、必要な検証を定めて実装へ引き継ぐ。見送る場合は再判断条件を示す。

## 検証・関連・合意

調査だけで実装や外部公開の試行を起動しない。実モデル比較が必要になった場合は、入力する公開資料・候補・依頼文、モデル、使用量と費用の扱いを確認した範囲で実行する。ローカルの未commit資料をGitHub Issueへ自動添付しない。成果物を変更して提出する場合は`bun run check`、独立評価と人向け日本語の確認を行い、実モデル結果と機械検証を分けて記録する。対象repoのcaptureは`null`で、画面媒体は不要。

[#139](https://github.com/thkt/dotagents/issues/139)は小さな実験への接続、[#157](https://github.com/thkt/dotagents/issues/157)は調査成果を読む入口、[#191](https://github.com/thkt/dotagents/issues/191)は同条件evalの入口を扱った。本Issueはそれらを再実装せず、scopingの参照分離候補の採否と今回必要な比較方法に絞る。

依頼者は参照の分離と確認を進める意向を示し、2026-09-24にこの候補を新Issueとして進めるよう指示した。今回は調査Issueの公開まで。参照分離の採用や、追加の実モデル送信・実装を先に承認済みとは扱わない。
