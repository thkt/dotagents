# 初心者向けフローHTMLから内部仕様の重複説明を整理する

## 目的と根拠

初めてハーネスを使う人向けのフローHTMLで、操作・判断に必要な説明を残し、CLI内部仕様と整理履歴の重複説明を減らす。

確認日: 2026-09-24。ローカル`docs/workflow-guide.html`はコード版`7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`を参照する。現在は「作り、確かめ、必要なところを直す」「検証した変更をPRへ渡す」の本文に、指摘IDの採番、保存形式の互換性、知識JSONの再解析省略、内部公開関数の型付き入力、stdout・stderrの保存順序などが並ぶ。同じ契約は[CLIガイド](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/README.md)と実装でも維持している。

内容が誤っているとの指摘ではない。入門の流れと内部の操作・保守仕様を手作業で同時更新する範囲を整理する。読解時間や保守費用の削減は未実測。

## 範囲と対象外

ローカルの現行ガイド本文を整理する。各説明が読者のどの判断・操作に必要かを確認し、内部詳細は既存のCLI正本や関連コードへ参照でつなぐ。必要な場合だけ図との説明を合わせる。全文を別文書へ複製・移動する対応、全文生成器、共通metadata、ライブラリ、表示モードの追加は行わない。runtime・検証定義・各工程の責任は変えない。

## 受入条件

- [ ] 入門本文から、各工程の入力、担当、実施内容、次へ進む条件、残る成果物、停止時の戻り先を読み取れる。
- [ ] 内部の採番・保存順序・処理最適化の説明は、通常利用者の判断に必要な部分だけを本文へ残す。削る詳細は既存正本の具体的な参照先へ辿れるようにする。
- [ ] 形式不正・保存障害・対象変化・公開結果不明を同じ成功や失敗へまとめない。文書の意味確認、必要媒体の実表示、readyと人の承認の違いを維持する。
- [ ] 旧形式runの扱いなど実際の開始・復帰判断に必要な制約は失わない。本文に残すか操作正本へ委ねるかを読者の判断に基づいて選ぶ。
- [ ] 同時に維持する説明箇所の減少と、残る参照確認の負担を示す。単なる行圧縮・ファイル移動や未観測の読解時間を削減効果に数えない。

## 検証と保全

着手時に現行ガイドと図を再確認し、変更前コピーをcheckout外へ保全する。確認時のガイドSHA-256は`09ec797d92346b462ffcfe8caa5b6b0dec139fc8b0ab2ab80312b3b84165f646`。既存の目次・節ID・リンクと参照版を保ち、通常幅・390px幅で本文、目次、根拠リンク、停止後の案内を確認する。日本語、条件、未確認事項を原資料・既存の独立評価へ照合し、変更提出前に`bun run check`を実行する。HTMLの画面確認と共通checkは別の結果として記録する。

現行HTML・画面証拠・生ログはローカル限定とし、公開repoへ追加しない。旧`workflow-guide-draft.html`や他の未追跡資産を更新・削除しない。
