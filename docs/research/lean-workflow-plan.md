# 運用とコードの両方を簡素化する修正計画

確認日: 2026-09-17。対象: thkt/dotagents、commit `0b3c61115337c15f14db41ea8f3fee5291497e45`。

依頼者は、任意化や最適化だけでは総コード量が増える可能性を確認した後、scopingで「運用とコードの両面でソリッドにする計画にして進めたい」と指示した。この計画は、その指示を反映したIssue改訂案と公開結果の記録を兼ねる。実装、現行方針への適用、commit、PR、マージは今回の要求整理に含めない。

## 目標と残す責任

合意した変更を人が根拠付きでレビューできる状態に届ける。不要な専用機能・状態・設定を廃止し、実行の手間と保守対象のコードを一緒に減らす。

| 責任 | 正本・担当 |
| --- | --- |
| 目的、要求、完了条件、合意と未決事項 | Issue・既存の下書き。重要な判断と権限は人 |
| 根拠、対象版、適用条件 | Issueから参照するコードと、必要なGit管理文書 |
| 調査、執筆、実装、内容の説明 | 担当AI |
| 実行順、対象照合、予算、停止、検証、公開確認 | 既存のホスト |
| コード・要求・テスト・文書の評価 | 既存の最終独立評価 |
| 受入、承認、マージ | 人 |

目指す通常経路は「要求を整理してIssueへ反映 → 実装・文書作成 → 必要な撮影とcheck → 独立評価・必要な修正 → PR公開と同じheadのCI → 人のレビュー・マージ」。要求整理用の専用セッションと文章校正用の別工程を外す。

## 既存利用・記録の保全と適用

旧セッション、校正の原文・候補・失敗記録、保存済みrun、lock、生ログ、worktree、他作業の差分は削除・変換しない。廃止するコードはGit履歴で辿れ、旧記録は参照資料として必要な事実だけ読む。旧実行を新しいruntimeで再開しない。

旧writing設定が対象repoやstandalone correction入力に残れば、対応終了と必要な変更を明示してモデル実行・公開前に停止する。設定を黙って無視しない。設定未指定でも校正が動く現行の既定動作も終了するため、共有ハーネスの利用先へ適用する前に方針・設定・稼働中の作業を確認する。他repoの設定や方針を一括変更しない。専用校正が必要な利用先は、切替前に方針を決め、未解決なら新版の起動を保留して旧版を保持する。

切替は採用commitからの新規実行を対象とし、進行中の旧実行を途中で差し替えない。復帰が必要なら、記録と作業差分を保全した上でコード・設定・方針を戻す。新規タスクでスキルとCLIの接続を確認し、ファイル変更だけで運用切替の完了としない。
