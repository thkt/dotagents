# Bunテストの成功行を抑え、skip拒否時の診断を残す

## 目的と確認した問題

`bun run test:control`と、それを含む`bun run check`で、成功したテストの個別表示を減らし、人とAIが結果を読み取りやすくする。成功件数・完了判定・失敗の診断は維持する。

2026-09-20、Bun 1.4.2、対象commit `8a89f33a06dfa75406f1d56113435e9dcf868690`の隔離コピーで、既存の`scripts/test.ts`へ`--only-failures`だけを加えて比較した。

| 条件 | 現行 | フラグ追加だけの候補 | 確認した結果 |
| --- | --- | --- | --- |
| 合成した成功テスト1,000件 | 1,009行 / 27,085 bytes | 7行 / 128 bytes | 両方終了0、件数・成功要約・完了表示を維持 |
| assertion失敗 | 16行 / 303 bytes | 15行 / 282 bytes | 両方終了1、失敗名・期待値・実値を維持 |
| skip | 12行 / 230 bytes | 8行 / 152 bytes | 両方終了1だが、候補のコンソール表示からskipしたテスト名・ファイル名が消える |
| 既存runner契約テスト | 9成功 / 0失敗 | 9成功 / 0失敗 | 現行テストではskip対象の表示欠落を検出しない |

onlyと構文エラーの拒否・診断も比較した。0件は両方失敗したが、観測した理由はJUnit未生成によるENOENTであり、専用の0件メッセージではない。アプリ側のconsole出力は残った。

現行runnerは最後にJUnitを削除するため、コンソールから消えたskip対象を終了後に確認できない。追加確認では、`--only-failures`付きでもJUnitにskip対象のテスト名・ファイル名・行番号が残ることを確認した。レポート保存を組み込んだrunnerの検証はまだ行っていない。

出力bytesの約99.5%減少は単純な合成fixtureでの値であり、実repo全体の削減率、トークン課金、速度改善は未測定。これらの数値を採用の完了条件にはしない。

## 範囲と方針

- `scripts/test.ts`のBun経路で、標準の`--only-failures`を使う。テスト対象と成功・失敗の判定条件を維持する。
- Bun自体は成功終了したが、runnerがJUnit集計のskipや不正を理由に拒否した場合、拒否理由と、原因を調べられる診断を残す。既に生成したJUnitを残して実際のパスを示す方法を最小案とする。
- 正常終了時は一時レポートを削除する。assertion失敗などBun自体が失敗した際は、既存の診断と後片付けを維持する。
- レポート未生成・読取り失敗も成功扱いにしない。存在しない、または利用できると確認していないレポートを「保存済み」と案内しない。
- `.codex/DEVELOPMENT.md`の「テストの実行完了」など既存の説明を、成功行の抑制、診断の参照方法、レポートを残す条件に合わせる。

失敗時に詳しい出力を得るための自動再実行は行わない。Playwright経路、アプリ側のconsole出力、テストの選択・件数、依存版は変更しない。汎用ログ収集、別ラッパー、XML全体の新しい解析基盤、レポート画面、恒久的なログ保管サービスは対象外。

## 完了条件

- [ ] 全テスト成功時は個別の成功行を抑え、件数の要約と`All tests executed.`を表示して終了0となる。一時レポートは削除される。
- [ ] assertion失敗・構文エラーでは終了1となり、失敗箇所や期待値・実値など、従来の原因調査に必要な診断を失わない。
- [ ] skipでは終了1となり、拒否理由に加えて、skipしたテスト名とファイル名を終了後の出力または案内されたレポートから特定できる。案内したレポートはrunner終了後にも存在する。
- [ ] only、0件、必要な集計の欠落・不正・切れたレポートを引き続き拒否する。読めたレポートの集計拒否では原文を確認でき、未生成・読取り失敗では実際の原因を示す。
- [ ] 成功時・失敗時の表示と保存条件を既存の説明に反映し、実装・検証結果と日本語の意味を照合する。

## 実装時の検証

セットアップは`bun install --frozen-lockfile --ignore-scripts`。既存の`scripts/tests/test-runner.test.ts`を拡張し、成功表示の抑制、診断の保持、skip時に案内したレポートの実在と内容、正常時の削除を振る舞いとして確認する。集計欠落・不正の組合せは既存の軽い直接テストを再利用し、実際の実装で変わる保存・失敗処理の境界だけを追加する。出力全文の固定比較や削減率の閾値は設けない。

提出前に引数なしの`bun run check`と独立評価を行い、PRでは同じheadの`checks`・`verify`を確認する。検証自体の変更なので、維持する保証、変わる表示・保存、未確認事項をPRに説明する。UI変更はなく、画像・動画は不要。実モデル評価やGitHub公開は制御テストとは別の証拠として扱う。
