# 調査報告とPR本文でnatural-japaneseを試した

調査報告1件とPR本文1件を推敲した。今回の自己確認では、結論を先に示すことと、長い文を分けることに用途があった。一方、通常lintは原文・推敲後とも指摘0件で、今回の改善候補は通読で見つけた。初回比較の時点では、既存レビューに推敲観点を加える案にとどまり、採用は未決定だった。

その後の限定適用の合意と実装範囲は[Issue #313](https://github.com/thkt/dotagents/issues/313)を参照する。本報告は初回比較と後続の別CLIセッションの記録であり、以下のlint・独立評価・`bun run check`の成功は各試行時点の結果である。今回の文書変更に対する最新の検証結果とは区別する。

Codexの同一会話内でクイック手順を各1回適用した。調査報告では `references/doctypes/report.md` を読み、PRには専用の文書型がないためスキル本体の共通観点を用いた。読者を採用・変更内容を判断する開発者とし、原文の事実、数値、否定、条件、権限、未確認事項、参照を維持することを優先した。過去の試行やPRの実装内容を再検証する作業ではない。

原文と推敲案に、同じスクリプトと設定で次を実行した。

```sh
uv run <skill-root>/scripts/lint.py <document.md> --genre tech --reading-load
```

`<skill-root>` は固定版の `skills/natural-japanese`。Python依存はスクリプト指定に従って取得したが、依存の解決版は記録していないため、完全に同じ環境の再現は保証しない。モデルの厳密な版・設定、使用量、総費用、推敲だけの所要時間は計測していない。スキルなしの独立した推敲対照群もないため、スキル固有の効果は分離できない。

## lintではなく通読で変更箇所を選んだ

| 検査 | 調査報告の原文 / 推敲後 | PR本文の原文 / 推敲後 |
| --- | --- | --- |
| 通常lintの指摘件数 | 0 / 0 | 0 / 0 |
| 読解負荷の補助指摘 | 1 / 1 | 0 / 0 |

調査報告の補助指摘は、未確認事項を並べた文の `buried_list` だった。短い一文で対象を読み取れるため残した。指摘を減らすための箇条書き化は行っていない。推敲後に新しい指摘はなかった。PR本文では箇条書きの一部が通常lintの本文解析から除外されるため、0件は全文の読みやすさを保証しない。

構造と読みやすさについては次のように判断した。

| 箇所 | 対応と理由 |
| --- | --- |
| 調査報告の冒頭 | 後半にあった手動プレビューへの適用判断と統合未検証の条件を冒頭にも置いた。結論と限界を先に読めるようにした |
| 調査報告の方法 | HTTP、接続先、ポート、環境設定の説明を分けた。表の値、コマンド、対象版、停止後の確認は保持した |
| PR本文のモデル起動前の説明 | 通常テスト、不具合注入、ホストの判定資料、出力との照合を別の文にした。物理的隔離・自動採点を保証しない条件も残した |
| PR本文の検証記録 | 「原実測」を「当初の実測」等に言い換えた。修正後に実モデル試行を再実行していないことを維持した |
| PRの見出し | 「変更と理由」「検証と修正」「適用範囲と限界」を維持した。レビュー時に探しやすいため、全見出しを結論文へ変える規則は一律適用していない |

例えばPRの「指摘と検証申告は出力へ照合して裁定します」は、「モデルの指摘と検証したという申告は、実際の出力と照合して判断します」とした。原文より長いが、誰の何を確認するのかを明示した。

## 意味を保ったかは数値と条件を別に照合する

自己確認では、調査報告の対象日・版・commit、二つのURLとポート、HTTP 200、タイトル差、localStorageの結果、停止後の状態、既存E2E未統合と未確認環境を照合した。PRでは対象commit、450件成功、3条件各1回、180秒・540秒・約289秒、検証根拠の再利用、常設テストの対象外、保存保証の限界、非公開情報の範囲、ready条件と人の承認・マージ判断を照合した。リンクとコマンドも保持した。

この確認は原文との意味の一致を対象とし、原文の事実が正しいことや現在も有効であることの再証明ではない。

独立評価では、初稿の「各条件で検出結果が異なることを確認します」が、3条件すべての結果が互いに異なるとの読みを生むと指摘された。原文の「不具合の検出差を確認」より断定が強いため、「条件ごとの検出結果を比較します」に修正した。推敲で意味が変わる危険を実際に1件確認しており、読みやすさだけの自己確認では足りなかった。修正後の全文を独立評価で再確認し、残る指摘はなかった。

推敲案と比較記録の日本語lintは成功した。修正後のPR案はnatural-japaneseの通常lint・読解負荷の補助検査も指摘0件だった。`bun run check` は450件成功・失敗0件で完了した。この共通checkはハーネスの制御テストであり、文書の意味の一致や読みやすさを測定するものではない。

## 人向け文書の推敲に限定して検討する

今回の2例では、書き方を見直す観点として使う余地がある。通常lintの追加検出はなく、読みやすさの改善も執筆担当の判断にとどまる。人の読解時間・理解度や、多数の文書での誤検出率は未測定である。

採用を検討する場合は、まず人が原文と推敲案を読み比べ、判断しやすくなったかを確認する。適用先は日本語の調査報告・PR本文とし、事実・条件・権限の照合を既存レビューに残す案を推奨する。フルモード、自然度スコア、並列の文書レビュー工程を常設する根拠は、今回の試行からは得ていない。

## 設定後に新しいCLIセッションで参照と適用を確認した

同日の後続確認では、依頼者が上記2種類への限定適用を指示した後、設定した作業ツリーを新しいCLIセッションから参照させた。上記までの採用未決定という記述は、最初の推敲比較時点の判断である。

Codex CLI 0.157.1、gpt-6-astra/high、`--ignore-user-config --ephemeral --approve-for-me --json` で各1回実行した。ユーザー設定は読み込まず、repoの指示と現在の作業ツリーを参照する条件とした。各セッションは180秒を上限とし、追加のモデル呼出しとGitHub操作を依頼範囲から外した。初回の基準commit `8d452eade4824e300b80b7b0b874595330976b53` に未コミットの設定差分を加えた版であり、デスクトップの新規チャットや他repoの試行ではない。

依頼にはスキル名を入れず、「このrepoの現在の執筆・確認手順」を使って原文を推敲するよう指定した。したがって、手順を読むという誘導はある。原文と現行方針以外の過去の推敲案・試行結果は読まないよう指定し、操作履歴でもそれらの本文取得は見つからなかった。両セッションは同じホストを使い、PR側は先の試行で取得した固定版と依存キャッシュを再利用した。環境を完全分離した比較ではなく、所要時間の優劣は判断しない。

操作履歴で、固定commitの照合、スキル本文の読取り、対象を指定したlintの実行結果を確認した。調査報告とPR本文の完成案は別のレビュー担当が原文と全文比較し、事実・数値・条件・未確認事項・参照・権限の欠落や断定の強化は見つからなかった。これは文章の意味の照合であり、元の実測やGitHubの現在状態の再検証ではない。

今回の条件では、スキル名を直接指定しなくても参照と適用を確認できた。常時の選択・遵守、他の文書・モデル・環境での効果、読解時間や理解度の改善、子モデルを含む総費用は未確認である。初回lintの成功率や実行時間を推定する試行数も足りない。生ログ・個人パスは公開せず、この要約と[調査報告案](natural-japanese-trial/report-session.md)・[PR本文案](natural-japanese-trial/pr-session.md)を共有する。
