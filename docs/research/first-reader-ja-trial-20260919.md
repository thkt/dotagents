### 初回の操作

抽出本文57・64行、HTMLの導入節に対し、読者役は「どこでどのように対象repoと依頼を渡してscopingを起動するのか」と質問した。[ガイド75行](../html/workflow-guide.html#setup)は実行コマンド・スキル登録等を別資料へ委ね、節末に参照先がある。[README](../../README.md)にも通常入口とスキルへの案内がある。リンクをたどって開始できるかは今回の試行対象外なので、本文内に手順を重複させる必要があるとは結論しない。

### 撮影再利用の条件

## 負担と限界

- 新しいコンテキストでのエージェント実行は2回。読者役と比較用の通常レビューを各1回行った。加えて主担当による入力抽出、結果照合、記録作成がある。
- モデルのトークン数と金額を取得していないため、費用は未測定。0円や低コストとは扱わない。正確な実行時間・人の作業時間も測っていない。
- 対象は1文書、各方式1回。人間の読者は参加しておらず、読みやすさの改善や翌日の記憶、再現性、検出率の向上は確認していない。
- 指摘を反映した文書の再評価は行っていない。元のガイド・スキル・ハーネス実装を変更せず、インストールやGitHubへの書込みもしていない。

### 次の実例で何を確かめるか

決めたいことは、実際の利用背景を与えた読者役が、一般的な読者役より人の迷いを捉えられるかである。EC画面への反応と文書の理解は異なるため、論文の正答率を受入基準にしない。

次に初見の人がガイドを利用する機会があれば、本人が行いたい課題、既に知っていること、読んだ文書の版と参照先、実際に選んだ次の操作・質問・説明が必要になった箇所を短く残す。人が読んだ結果を先に記録し、AIの指摘で誘導しない。個人を再現するための属性収集や、常設の記録基盤は作らない。

観測がない現在は、次の2課題を候補とする。これは人工的に定めた課題案であり、実際に人が失敗した事例ではない。必要性は初回の観測から見直す。

- 導入時に、設定の配置先・相談する入口・実行前に足りない情報を説明できるか。
- 公開結果が`unconfirmed`のとき、次に確認する対象と、実状態を確認する前に再実行してはいけない操作を説明できるか。

設定を作る観測と評価する観測は、文書・課題・作業のまとまりで分ける。評価側は少なくとも未使用の2課題を候補とし、設定に使った話題の言い換えや同じ問題の別ターンを持ち込まない。初見の理解を扱うため、評価する人が既に答えやAI指摘を見ていないことも確認する。適切に分割できなければ実行条件は未充足とする。

### 観測が揃った場合の最小比較案

| 項目 | 試験案 |
| --- | --- |
| 条件A | 一般的な読者設定だけを与える。Git/GitHubの知識なども、対象読者に本当に適用する範囲だけ指定する |
| 条件B | Aに、別の観測から確認した利用目的・既知の知識・利用上の制約を加える。評価対象で起きた質問、正解、失敗、改訂理由は渡さない |
| 共通入力 | 同じ文書・課題・モデル・設定・出力形式・参照可能範囲。読者が使えるリンク先も、同じ固定版を両条件へ渡す。前回のように片方だけコードを読める比較にはしない |
| 共通の出力 | 要点、次にできる操作・判断、根拠箇所、未解決の問いを最大3件。指摘0件を許容し、意図的な反対意見は求めない |
| 実行単位 | 2課題 × 2条件を各1回、計4回の探索的試行。毎回新しいコンテキストにし、他条件の出力を渡さない。ケース名・パスにも正解や条件の良し悪しを示す名前を使わない |
| 裁定 | 出力を保存してから、人が実際に示した質問・操作結果と照合する。読者の反応との一致、本文・参照先で確認できる説明不足、根拠のない断定、未確認を分ける。採点時にA/Bの名前を隠しても、文面から条件を推測できる限界は残る |
| 費用 | 入力準備、人の観測、AI実行、裁定を分け、経過時間・取得可能なモデル使用量・ツール呼出しを残す。失敗した呼出しも含める。課金額を取得できなければ未測定とし、呼出し回数を金額と扱わない |

4回は手順が機能するかを見る上限であり、精度を推定するための十分な標本数ではない。失敗した出力を黙って差し替えたり、良い結果が出るまで実行したりしない。設定作成に追加のモデルを使った場合は、その費用も分けて記録する。

人が迷った記録がないことを「問題なし」の正解ラベルにしない。問題なく課題を完了した観測も比較に含めるが、その観測だけで文章に他の問題がないとは保証しない。見落としは事前に記録した観測上の迷いに限って数え、AIが新たに示した未観測の懸念は自動で誤指摘にしない。率を出す場合は分母を明示し、判定不能を除いて見かけの成績を上げない。

Bでだけ確認できた追加の有用な指摘、増えた根拠のない断定・費用、条件を変えても変わらなかった判断をまとめる。これだけで常設採用せず、追加検証の価値があるかを判断する。判断を変える差が出なければ、読者設定や呼出しを増やす根拠とはしない。

改訂前後の文書を並べる試験は今回は含めない。読者設定の効果と質問形式の効果を混ぜないためである。後で行う場合は旧版・新版の名称を伏せ、提示順を入れ替え、初見の理解試験とは別に扱う。
