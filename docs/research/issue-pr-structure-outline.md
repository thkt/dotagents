## 目的と現在の不足

PRを読む人が、変更の理由に加えて、呼出順序・データ形状・責務のどこが変わるかを短く把握できるようにする。評価の各区分や定型手順による重複を減らし、公開後に長い本文を縮め直す負担も減らす。

現行の[評価指示](https://github.com/thkt/dotagents/blob/e0264ad7803965074af5e998e06f04643408ed88/scripts/review.ts)は、`assessments.code`に具体的な変更と理由を書くよう求めているが、構造の説明が役立つ場合の表現を示していない。[PR本文生成](https://github.com/thkt/dotagents/blob/e0264ad7803965074af5e998e06f04643408ed88/scripts/pr-body.ts)は、その文字列を「変更と理由」へ配置しており、複数行のMarkdownを使える。

visual-prから、変更に合う最小限の構造説明を選ぶ考え方を取り入れる。全PRで図を必須にはせず、読みやすさの改善量も現時点では未測定とする。

2026-09-20の追加調査では、main `e0264ad7803965074af5e998e06f04643408ed88`の[生成処理](https://github.com/thkt/dotagents/blob/e0264ad7803965074af5e998e06f04643408ed88/scripts/pr-body.ts#L37)が、評価4区分・指摘への対応・文書説明・定型手順を順に展開していることを確認した。PR #160の保存済み生成本文は修正後4,413字、担当AIが整理した本文は1,427字だった。単一例の文字数であり、短さだけを十分性や一般的な効果の証明にはしない。内部記録を減らさず、既存の生成経路で必要な公開説明を一度ずつ示す改善を、本Issueの範囲へ合わせる。

## 今回の範囲

- 既存の評価指示へ、構造を示すと理解しやすい変更では、短い呼出経路、型・データ形状、責務の対比などを「変更と理由」に添える方針を加える。既存構造の変化は短い差分、新しい構造は必要な部分の全体像を使い、文章だけで十分な変更では省く。
- 実際の差分と関連コードを根拠にする。説明用の概略・擬似コードはその旨を示し、判断に必要な条件、失敗時の挙動、実行順序、担当の違いを省略で変えない。未実装の構造を実装済みとして示さない。
- `assessments.code`から既存のPR本文へ渡す経路を使う。生成処理は、不足が確認された場合だけ必要な範囲で変更する。説明が必要な既存文書も、この方針と整合させる。
- 要求との対応、検証と未確認事項、対象commit、指摘への対応、文書と根拠、残作業と担当は維持する。外部テンプレートの固定文数・固定項目数は採用しない。
- 同じ変更・結論・但し書きを複数区分で繰り返さないよう、既存の評価指示と本文生成の分担を整理する。定型操作の詳しい説明は既存ガイドを参照できる形へ寄せ、PR固有の条件・未確認事項・残作業と担当は本文に残す。通常の残作業を完了済みと誤記しない。
- 既存PRの修正では、現在も必要な変更説明・未解決事項・添付リンクを保ち、以前の反復過程や古い成功説明を累積させない。自由文の類似判定による自動削除器、文字数による切捨て、別の要約モデルは追加しない。必要な内部評価・指摘履歴・生ログは保全する。

新しい評価項目・専用モデル呼出し・校正工程・スキル・保存台帳は追加しない。visual-prのインストール、commitやpushの手順移植、画像・HTMLの必須化は対象外。公開本文の確認責任の見直しは #128で扱い、本Issueでは変えない。

## 完了条件

- [ ] 指示が構造説明の利用条件と省略条件を示し、すべてのPRに図や定型の構造欄を要求していない。
- [ ] 構造が変わる具体例と、文章だけで足りる具体例を、実際の差分に照らして確認する。前者では変更箇所と理由が対応し、後者では不要な図解が増えない。説明の短さだけを採用理由にしない。
- [ ] 生成される本文で、説明に使う改行・コードブロック・差分記号が保たれ、既存の内部パス省略と必須情報の出力が壊れない。必要な確認は既存のPR本文テストを使い、不足する場合だけ追加する。
- [ ] 既存の独立評価で、説明と対象版の整合、重要な条件の保持、日本語の明瞭さを確認する。指示や定型入力のテストだけで、モデルが常に従う・読解時間が短縮したとは結論しない。
- [ ] 既存の具体例で生成前後の本文を比較し、同じ結論・定型手順の反復が減り、条件・否定・権限・未確認事項・担当・必要な添付リンクが残ることを確かめる。文字数の上限や見出しの綴りだけを固定するテストは作らず、既存の正常系・異常系で公開情報の保持と内部情報の保護を確認する。
- [ ] 実装・テスト・文書の増減と、実際に省ける生成・編集・転記を既存PRへ短く記す。本文が短くなっただけの場合は、実行ノード・矢印の削減に数えない。専用の測定基盤は追加しない。
- [ ] `bun run check`と既存の公開手順を満たし、実装PRには確認した例、確認方法、未確認の限界を簡潔に残す。
