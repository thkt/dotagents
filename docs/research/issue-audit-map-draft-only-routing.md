# 構成図の下書き限定経路を公開権限確認から分離する

## 目的と根拠

ローカル構成図で「案だけ・公開しない」の依頼に公開準備が先行する表示を直し、下書き作成に不要なGitHubの権限確認を前提にしない。

確認日: 2026-09-24。ローカル`docs/workflow-map.html`の参照コード版は`7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`。現在の接続は`S23 → I01 → I02 → I03 → I04 → I05 → I07`で、公開しない経路は最後の`I07 → I08`で分かれる。`I01`は`target.ts --write`による対象・主体・push権限確認を説明している。

[scopingの公開範囲](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/scoping/SKILL.md#L50)は、案だけならローカル下書きで終了し、公開・更新するときに[Issue反映手順](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/scoping/references/issue.md#L3)へ進む。図の不整合であり、担当AIが実際に不要なCLIを呼んだという観測ではない。

## 範囲と対象外

ローカルの構成図を修正し、ガイドに同じ誤解を招く説明があれば必要な箇所だけ揃える。runtime・権限要件・スキルの許可範囲は変更しない。HTML・画面証拠・生ログを公開repoへ追加しない。

## 受入条件

- [ ] 案だけ・公開しない依頼は、必要な事実調査、下書き作成、内容精査から提案の報告へ進み、公開用の`target.ts --write`を必須経路として通らない。
- [ ] Issueを公開・更新する依頼では、既存の対象・主体・権限と公開直前の再照合、公開後の読戻しを維持する。既存の合意を聞き直す待機点は追加しない。
- [ ] 公開許可が未確定なら依存する書込みを止め、許可済みの独立した調査・下書き作成を続けられることを表す。指定Issue等の必要な読取りまで禁止する図にしない。
- [ ] 既存の条件分岐とノードを再利用し、必要な条件・責任・根拠・停止先と担当を保つ。接続の訂正・統合時も既存IDの検索・直接参照を維持し、別の状態管理・gate・表示モードを加えない。

## 検証と保全

着手前に現行HTMLの内容・hash・参照版を再確認し、checkout外へ比較用コピーを保全する。現在の図のSHA-256は`9ff7de1d20c845922d5103fd3268cecd6c38d2b492ea51688a7aac88b5185407`。後続の更新があれば最新差分を読み、古い版で上書きしない。

案だけ、公開許可あり、公開権限未確定の経路を静的にたどり、通常幅と390px幅で工程表示・接続図・検索・停止表示を確認する。日本語と責任分担を原資料・既存の独立評価へ照合し、変更提出前に`bun run check`を実行する。画面証拠はローカルに保管し、図の接続整理と実行回数の削減を区別する。
