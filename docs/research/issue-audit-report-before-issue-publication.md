# 調査: 初回Issue公開前に調査報告の参照を準備できる条件を確認する

## 調査の目的と根拠

必要な調査報告の参照を初回Issue公開前に揃えることで、公開後の追記・読戻しを減らせる条件があるか調べる。現行手順の変更や機能実装の採用は、このIssueに含めない。

確認日: 2026-09-24。対象版: `7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`。ローカル構成図には`I11/I12 → I13 → H02 → H06 → H07`という接続があり、Issue公開後に報告を保存・commitし、参照をIssueへ追記する流れを表す。

[scoping](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/scoping/SKILL.md#L42)は報告の事前保存を禁止していない。[引き継ぎ手順](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/scoping/references/session.md#L15)は保存・commit・共有を区別し、[Issue反映手順](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/scoping/references/issue.md#L15)は報告commit・Issue更新後の再照合を要求する。図の順序だけで、実運用でも常に二段公開しているとは断定できない。発生頻度、時間、誤り率は未確認。

## 調査範囲

既存の手順・コード・取得できる保存記録から、次を確認する。確認できない点は未確認として残す。操作回数を測るためのIssue作成・更新やcommit・pushは行わず、実装CLIを起動しない。調査結果を本Issueへ記録する操作は含む。

- 必要報告がない場合、既に確認・commit済みの場合、新規報告を作る場合で、実際に必要な操作を区別する。
- 報告の確定にIssue番号・要求合意・別の変更やPRが必要な場合と、既存の許可範囲で先に参照を準備できる場合を区別する。
- commit・共有の許可不足、報告未共有、内容変更、開始commitとの不一致では、どの操作が先行でき、何を待つ必要があるか確認する。
- 「参照を含めて一度に初回公開する」「公開後に必要な参照を追記する」の適用条件と、操作・保守の負担を比較する。公開後に根拠が変わるケースを初回公開へ無理に集約しない。

## 完了条件

- [ ] 現在の手順が要求することと、図が一例として描く順序を区別し、実際の重複操作が確認できたかを示す。保存記録の欠落や仮想例を実測と扱わない。
- [ ] 事前準備が成立する条件と成立しない条件を、既存の要求・権限・報告版・共有状態へ対応づける。必要報告を増やさず、Issueと出典で足りる経路を保つ。
- [ ] 確認済みblobと開始commitの一致、内容・合意の確認、更新後の読戻し、他担当の変更保全を維持できるか説明する。
- [ ] 現状維持・順序整理の候補・根拠不足による保留のいずれかを、理由と再判断条件とともにIssueへ記す。後続変更が必要なら範囲案を示し、採用済みと扱わない。

## 検証・対象外

結論は原資料と既存記録へ照合し、日本語の条件・権限・未確認事項を確認する。必要な独立評価は既存の方法を使う。読解だけの調査に共通check・実モデル・公開試行を追加しない。リポジトリ文書を変更する場合は現在の文書方針と`bun run check`を適用する。

新しい引き継ぎCLI、入力形式、台帳、gate、hashの自動差替え、共有範囲の拡張は対象外。ローカルHTMLや画面証拠・生ログは公開repoへ追加せず、結論と判断に必要な根拠を本Issueへまとめる。
