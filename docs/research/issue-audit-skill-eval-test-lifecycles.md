# skill-evalの直列統合テストを、停止境界ごとに独立させる

## 目的と現在の根拠

スキル評価のテストで、先行ケースの失敗や変更済みの環境が、別の停止条件の検証を妨げる構造を減らす。調査版はmain `7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`。

[skill-eval.test.tsの統合ケース](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/tests/skill-eval.test.ts#L358)は574行まで、正常なpaired run、報告根拠の照合、network/cleanup/timeout、不完全なペア、割込みを1ケース・同一環境・30秒上限で直列実行する。先行assertが失敗すると後続条件まで到達しない。

## 範囲と受入条件

- [ ] 正常な実行と入力秘匿、報告の根拠照合、隔離失敗・cleanup失敗・timeout、ペア欠落、割込みを、守る停止境界に応じて独立して実行・診断できるケースへ整理する。行数だけの分割はしない。
- [ ] repo準備・fake Docker・環境変数の復元は必要な範囲で共有し、各ケースの状態・出力先・後片付けを独立させる。環境変数を使うケースを無条件に並列化しない。
- [ ] 未commit情報・期待ラベル・認証情報の非混入、隔離失敗時の起動抑止、未評価を含む分母、実行失敗と判定不能の区別、証拠のhash/行範囲、既存出力保全、割込み後のcleanupを維持する。
- [ ] 報告だけの不正入力は小さい保存記録fixtureで確認できる範囲へ寄せ、実行から報告への結合確認は残す。障害条件を削って短くしない。

評価runtime、モデル呼出し上限、Docker隔離、採点規則、成果物形式、実モデルevalは対象外。新しいテストDSL・台帳・計測基盤を作らない。

## 検証

既存の模擬Dockerによる制御テストで、各停止理由・後続起動抑止・保存記録・元作業の保全を同条件で確認する。環境や実行順への依存がないことを、影響するケースに絞って確認する。対象は`thkt/dotagents`。実装時は`bun install --frozen-lockfile --ignore-scripts`で準備し、影響する既存テストと提出前の`bun run check`、差分の独立評価を行う。PR公開時は同じheadの`checks`・`verify`を確認し、人がレビューとマージを判断する。画面変更はなく、媒体は不要（既存の`capture: null`を維持）。
