## 目的と根拠

同じ工程境界で連続する対象照合を削り、既存PR修正の外部参照と失敗経路を減らす。[verify終了時](https://github.com/thkt/dotagents/blob/0fec56c536763f8ccbd4bc4a9080c19beb14862d/scripts/development.ts#L485)に `revisionUnchanged` を実行した後、[ship](https://github.com/thkt/dotagents/blob/0fec56c536763f8ccbd4bc4a9080c19beb14862d/scripts/development.ts#L523)は結果案内のメモリ上の更新だけを挟んでもう一度同じ照合を行う。

隔離コピーと既存revision fixtureで確認した。この区間ではGitHub参照コマンド12回とGit参照10回が実行され、後者の呼出しを外すとGitHub参照は6回になった。変更後の関連29テストと観測用1テストは成功した。Gitは一時repo、GitHub・モデルは模擬応答。観測用試験では検証処理も模擬化しており、その内部参照数は含まない。実運用の速度や障害率の改善は未測定。

## 範囲と受入条件

- [ ] 検証から戻ってcommit準備へ入る同一境界の `revisionUnchanged` を一回にする。既存の責務へ集約し、照合結果の汎用キャッシュや新しい管理層を追加しない。
- [ ] Issue・修正入力・対象repo・設定・主体・権限・既存PRの不一致を残る照合で拒否し、commit・push・PR更新へ進まない。
- [ ] setup・モデル実行・commit・pushなど状態が変わる作業を挟む照合は維持する。特にcommit前後のverifyを今回の重複と混同しない。
- [ ] 成功・停止結果、旧runの保全、新規実装とno-publishの動作を維持する。

関連は #104。主な検証は `revision.test.ts` と `development.test.ts`。呼出回数の削減だけでなく、対象変更時の停止と公開抑止を確認する。現行図では操作内に含まれる細目であり、ノード・矢印の純減は見込まない。

## 検証・削減評価・引き継ぎ

セットアップは `bun install --frozen-lockfile --ignore-scripts`。変更の提出前は `bun run check` と差分の独立評価を行い、PRでは同じheadの `checks`・`verify` を確認する。既存の関連テストを使い、不足する現実的な失敗条件だけ追加・更新する。プロダクト画面媒体は不要。

実装・テスト・文書の増減と、同じ範囲・粒度でのノード・矢印の増減を既存のPR説明に記す。実際の処理・操作の削減と表示上の集約を区別し、純減がなければその理由を示す。行の圧縮、単なる移動、新しい計測基盤・必須帳票は目的にしない。変更を挟む再照合、停止時の保全、独立評価、人の要求判断とマージを維持する。
