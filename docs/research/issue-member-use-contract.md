# メンバー利用に向けて共有入口と変更時の確認を揃える

## 目的

複数のメンバーが共通ハーネスを使う際、依存してよい入口と、更新で守るべき振る舞いを同じ説明から判断できるようにする。現在のREADMEは`scoping`・`implement`とCLIの起動方法を示し、Fallowはrepo内の未使用exportを検査している。一方、未使用判定だけではメンバーが使う入口の互換性を証明できない。

確認版は2026-09-23の[main `53b38db` のREADME](https://github.com/thkt/dotagents/blob/53b38db77233ad1b45f90cdad1aa24562750463c/README.md)、[実装入口](https://github.com/thkt/dotagents/blob/53b38db77233ad1b45f90cdad1aa24562750463c/skills/implement/SKILL.md)、[対象設定](https://github.com/thkt/dotagents/blob/53b38db77233ad1b45f90cdad1aa24562750463c/scripts/target.ts)、[未使用検査設定](https://github.com/thkt/dotagents/blob/53b38db77233ad1b45f90cdad1aa24562750463c/.fallowrc.json)。[Issue #54](https://github.com/thkt/dotagents/issues/54)は共通環境への切替、[Issue #174](https://github.com/thkt/dotagents/issues/174)は未使用検査の導入を扱った。本Issueはメンバーが依存する入口を揃える範囲に限る。

背景: [Hermesの大規模リファクタリング](https://nousresearch.com/refactoring-hermes-with-1393-agents)では、repo内に参照がない公開名を削除し、外部プラグインの利用を壊した。こちらのハーネスにも同じ外部プラグイン利用があるとは確認していない。今回の対象は、メンバーが使うことを想定する共有入口である。

## 範囲

1. 現行の`scoping`・`implement`、対象repoの`.dotagents.json`、案内しているCLI起動方法から、メンバーが依存してよい入口とその前提を列挙する。実装内部のTypeScript exportや、単に参照されているだけのファイルを自動的に公開契約とは扱わない。実行結果の参照方法は、既に利用者向けに案内している範囲だけ確認する。
2. 入口ごとに、変更時に保つ条件と、意図して変える場合に利用者へ伝える内容を既存のREADME・CLI手順・開発方針の正本へ整理する。過去の移行経緯や全内部API一覧を新しい正本にはしない。
3. 今回特定した契約について、既存テスト・検証で守れる条件と不足を確認する。必要な不足だけに検証を追加し、静的な未使用判定を互換性の証明として扱わない。

## 完了条件と検証

- メンバーが現在使う入口、必要な設定・版、結果の参照先、変更時の確認点を、既存の読む順序から辿れる。
- 入口の削除・名前や設定の変更が内部整理か利用者に影響する変更かを、実際の利用条件と照合して判断できる。
- 守ると決めた契約について、変更前後の観測可能な結果と失敗条件を確認し、既存検証で不足する場合だけ回帰検証を加える。
- `bun run check`と変更に関係する実際の入口確認を実施し、未確認のメンバー環境や外部利用は未確認として記す。

## 対象外

大量の並列エージェント実行、行数削減の目標、全exportの固定、全repoの一括リファクタリング、新しい互換性台帳や専用スコア基盤。

## 合意と未確認

メンバーで共通ハーネスを使い、揃える方向は依頼者が示した。本Issueは、そのためにメンバーが依存する入口と更新時の確認を最初の範囲とする。導入手順・版は入口の前提に必要な分だけ扱い、コード整理・レビュー基準の全面改訂には広げない。

メンバーごとの環境と、repo外から内部TypeScript exportを利用する実例は未確認。現時点でそれらの互換性を保証したとは扱わず、利用実態が見つかった場合は必要な対象を明示して範囲を再評価する。
