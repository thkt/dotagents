# 構造図・HTMLとコード全体のJev監査

2026-09-18 JST。対象コードは公開済みの [7e1d69b](https://github.com/thkt/dotagents/commit/7e1d69b550197fa343c0e4bd7246a6ab503585d0)。Jevの候補判定と担当AIのコード照合を組み合わせた調査で、変更の実装は行っていない。

## 結論

構造図には、終了済みrunの経路について現行コードと合わない接続が2か所あった。ガイドと図のPR生成説明にも、定型の残作業をホストが付ける責任分担を補う余地がある。これらを既存のIssue #106へ引き継ぐ。

表示を簡潔にする候補は、十分性の六観点と独立評価の四観点の集約、および同一内容のガイドと下書きの編集元一本化。いずれもIssue #106の既存範囲であり、新しい発見として数えない。モデル呼出しや必要な検査が減るわけでもない。

コード側は既存Issue #99〜#102の共通指示・固定メタデータ・取得共用が引き続き候補。今回の広い判定では、それら以外に、そのまま削除できる処理やテストを確定できなかった。「不要なコードが存在しない」という結論ではない。

## 構造図・HTMLの確認結果

### 終端判定前の知識読込み

図は `V04 → V16 → V05` で、V16「選択知識を読み、実行状態を確定する」の後に終端結果の有無を判断している。[現在のexecute](https://github.com/thkt/dotagents/blob/7e1d69b550197fa343c0e4bd7246a6ab503585d0/scripts/correction.ts#L854)は `state.result` があれば照合して返り、知識の再構成は未完了経路だけで実行する。[PR #107](https://github.com/thkt/dotagents/pull/107)で実装済みの省略が図へ反映されていない。

V16は未完了経路に必要。ノードを丸ごと削除するのではなく、終端分岐を先に置く。これは図の経路修正であり、新たに実行時間やコードが減る変更ではない。

Jevの局所確認は「現行コードは読込み前に終端return」0.94、「図は読込みが先」0.73。一方、総合的な不整合の問いは0.37で、結論が揃わなかった。指摘の根拠は担当AIが確認した実際のコードと接続データであり、Jevの総合判定ではない。

### 保存済み結果の返却と新規保存

図の `V06 → V13` は「同一・accepted」をV13「ready_for_human_reviewを保存する」へ接続する。現在の終端経路は、[保存処理へ進まず結果を返す](https://github.com/thkt/dotagents/blob/7e1d69b550197fa343c0e4bd7246a6ab503585d0/scripts/correction.ts#L864)。新規結果の保存と既存結果の返却を、接続と説明で区別する。

「終端で再保存するか」のJev回答は0.08、「図は保存ノードへ接続しているか」は0.93。なお、広い判定でJevがstaleとした `V06 → Z01` は削除根拠にしなかった。現在も、対象が同じなら以前の停止結果を返す経路は必要である。

### PR生成の責任分担

図R11・P06とガイドのPR生成説明は、評価結果から引き継ぎを選ぶ説明が中心。[現在のreviewInstructions](https://github.com/thkt/dotagents/blob/7e1d69b550197fa343c0e4bd7246a6ab503585d0/scripts/review.ts#L245)はIssue固有の残件だけをAIへ求め、[PR生成](https://github.com/thkt/dotagents/blob/7e1d69b550197fa343c0e4bd7246a6ab503585d0/scripts/pr-body.ts#L58)が定型の公開・CI・人の判断を追加する。[PR #108](https://github.com/thkt/dotagents/pull/108)後の分担を補い、図から定型文の再生成を復活させない。

### 表示上の集約

- S16〜S21とR07〜R10を各1ノードにまとめ、内部の接続だけを省く静的計算は、202→194ノード、318→310接続。個々の評価項目・根拠は残す。レビューは既に1回のモデル呼出しであり、4回から1回に減る変更ではない。
- 停止種別の接続は96本。通常表示で畳む案はあるが、発生元・条件・戻り先の区別を削除しない。
- ガイドと下書きは109,428 bytesで完全一致。編集元一本化は二重保守を減らせるが、旧資産の削除許可ではない。
- 構造データで、存在しない接続先、完全に同じ接続、E01から到達不能なノードは各0件。到達可能性は条件を無視したグラフ確認であり、すべての実行経路が正しい証明ではない。

## コードの候補と照合

Jevの全体分類では、コード10ファイルとHTMLのJS1本について重複・冗長の候補が出た。各トップレベル単位の分類はすべてkeepで、ファイル全体の問いと整合しない部分がある。追加で具体的な単位を選ばせ、選ばれた関数・テストを担当AIが読み直した。

| 対象 | 照合した用途と扱い |
| --- | --- |
| `correction.command` | exit・pipe終了・close・kill後のpollはプロセス完了を捕捉する別経路。特定の不要な処理を確定できず、削除候補にしない。実行管理の依存整理は既存#98 |
| `development.verifyStartInputs` | 開始HEADの前後照合、設定本文、報告blob、index・modeの照合は対象や検出条件が異なる。2つのcheckoutも別対象。単純な重複削除にしない |
| `evidence.renderEvidence` | 現在の実測と過去版の実測・限界を区別して描画する。似た項目名だけで履歴説明を削除しない |
| `publish.publish` | 対象解決後と作成直前の主体確認、新規・既存PRの確認には異なる時点・入口がある。同一観測の共用を調査する#102の範囲で扱う |
| `target.pushArguments` | 設定したpushurlとinsteadOf展開後の送信先は別の検査。単純削除しない |
| `target.argv` | 先頭要素の空白拒否と全引数の文字列確認を含む。似た型検査という理由だけで削除しない |
| `ci.test` / `review.test` | 再質問でも削除箇所が定まらないものがあった。異なる異常入力・期限・履歴破損を守るケースを減らす根拠にはならない |
| `knowledge.test` | 初回実装・修正・評価への同じ根拠の受け渡しと、停止済み記録・blob欠落などを確認する。別々の出力先と失敗条件を単なる繰り返しと扱わない |
| `publish.test` のafterEach | Jevは冗長候補に選んだが、空の `withInterrupts` 呼出しで次のケースへ割込み状態を残さない用途があるため削除しない |
| `review.test` のreviewer / 共有fixture | 共通の模擬応答を既に再利用し、ケース固有の不正応答を作る役割がある。Jevの高めの選択確率だけで更なる抽象化や削除を採用しない |
| HTML描画JS | 描画中にnodes・edgesを繰り返しfilterする箇所はあるが、意味のない処理とは未確認。別indexを増やす保守負担と応答性能は未比較。最適化の確定候補にしない |

静的な補助確認では、空白正規化後に完全一致する120文字超のトップレベル単位、複数ファイルにまたがる140文字超・6行の完全一致窓は検出しなかった。これは意味の近いコードの不存在を示さない。識別子の他ファイル出現表も字句検索であり、動的参照・外部利用を含めた到達可能性解析ではない。

## 実行記録と限界

- 使用モデル: 全成功応答で `jev-1.13.0`。
- 成功したHTTP呼出し65回、1,017問。最初の全体分類985問に、候補の特定20問・局所事実12問を追加した。これらは正解率の評価件数ではない。
- API申告: 入力1,059,023 tokens、出力57,970 tokens。共有contextを多く渡した監査であり、省コスト性の実証ではない。
- 応答受信までの単発計測206〜1,269ms、合計33,675ms。一部は並列で、準備・読み取り・照合・記録を含む総作業時間ではない。
- 1リクエストは入力上限でHTTP 400となった。失敗入力を保持し、未完了分の長い参照資料を関連箇所へ絞って完了した。成功済み入力は再送していない。最初のsandbox内実行はDNSエラーで送信前に停止した。
- 最初のChoice分類はkeep 960、duplicate 6、redundant 5、display_group 13、stale 1。分布やkeep件数を監査の合格数にしない。
- 専用MCP・router・パッケージを追加せず、[公式HTTP API](https://docs.typesafe.ai/api)を直接使用した。型付き質問は[Choice](https://docs.typesafe.ai/primitives/choice)と[Noul](https://docs.typesafe.ai/primitives/noul)。コード・HTMLは判定資料として扱い、実行ログや認証情報は入力に含めていない。
- Jevは分類・確率を返し、根拠説明を生成していない。本報告の理由と採否は担当AIの照合結果。独立した正解ラベル、反復安定性、別評価者による独立評価、削除後の動作比較は未実施。
- `bun run lint` は成功。製品コード・HTMLの変更はないため、full check・ブラウザ動作試験・実運用の削減量測定は実行していない。

送信入力・出力、ファイルハッシュ、対象一覧、静的集計は既存のcheckout外の試験保存先に保持した。後続作業はIssueの記載と公開済みの版付きコードから判断でき、生ログやローカル保存先を必須入力にはしない。
