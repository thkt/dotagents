# 型チェックをすり抜ける型変換と累積コピーをlintで防ぐ

## 決定と状態

2026-09-23の対話で、依頼者はanti-slopの取り込みを「型チェックをすり抜ける型変換」と「蓄積結果の反復コピー」の2観点に限定する方針を示し、限定試行の結果を受けてIssue化・実装への進め方を相談した。本Issueでは、この2観点を通常のlintで検査し、違反時に停止する制約として実装する。許される書き方を絞って実装・レビューの判断を揃える。

Issue作成時点で本番のlint設定・依存・ソースは変更していない。実装と共通checkへの追加は未実施。Issue本文の独立評価は未実施。

## 目的と範囲

AIが選ぶ実装とレビューの判断を揃えるため、2観点の禁止パターンを機械的に検出する。規則の数だけを増やさず、直し方を説明でき、日常的な例外処理を増やさない制約を選ぶ。現行コードの指摘件数だけで判断せず、将来の変更で防げる具体的なパターンも確認する。

| 観点 | 実装案 | 維持する実装 |
| --- | --- | --- |
| 型検査を通さず型を狭めるアサーション。連鎖した変換や、型を広げた変数を介する変換を含む | Oxlint標準の`typescript/no-unsafe-type-assertion` | `unknown`で受けた外部入力の値検査、型ガードによる絞り込み、`as const` |
| 蓄積結果を反復ごとにコピーする | anti-slopの`no-reduce-accumulator-copy`、Oxlint標準の`oxc/no-accumulating-spread` | 新しく作ったローカル配列への追加、入力要素単体のコピー |

適用範囲は既存lintと同じ`scripts/**/*.ts`とし、テストも含める。`typeof`・`unknown`の一般的な禁止、型アサーションの全面禁止、命名・空行の規則、filter/mapの一律禁止、Effect固有の規則は今回の対象に含めない。外部入力の検証は[開発方針](https://github.com/thkt/dotagents/blob/16d70c23918d69d4dbc01795ac1a886938ee573d/.codex/DEVELOPMENT.md)を維持する。

## 確認した根拠

- 対象ハーネス: [16d70c23918d69d4dbc01795ac1a886938ee573d](https://github.com/thkt/dotagents/tree/16d70c23918d69d4dbc01795ac1a886938ee573d)のcheckoutにある`scripts/**/*.ts`。試行対象40ファイルの一時コピーと元ファイルの内容一致を確認した。
- anti-slop: [c44ef22ca116d0ba62a3ff663a0bd13a3f3fa40b](https://github.com/dmmulroy/anti-slop/tree/c44ef22ca116d0ba62a3ff663a0bd13a3f3fa40b)。初回は独自3ルールと共通ファイル1個、計646行を一時領域で使用した。標準ルールとの比較後は、[累積コピーのルール](https://github.com/dmmulroy/anti-slop/blob/c44ef22ca116d0ba62a3ff663a0bd13a3f3fa40b/src/rules/no-reduce-accumulator-copy.ts)と共通ファイル1個、計203行で同じ問題例を検出できた。いずれも別途小さな登録用コードが必要になる。
- 実行環境: Node.js 26.10.0、Oxlint 1.80.0、`@oxlint/plugins` 1.80.0。追加依存は一時領域だけに取得し、インストールスクリプトは無効にした。
- 比較元: 現行`.oxlintrc.json`。初回は独自3ルールと標準のspread検出、最終案は標準2ルールと累積コピーの独自ルールを同じ適用範囲へ追加した。自動修正は行っていない。

型の標準ルールは、型情報を利用して安全でない絞り込みを検出する。仕様の参考は[typescript-eslintの説明](https://typescript-eslint.io/rules/no-unsafe-type-assertion/)で、今回の可動確認は導入済みOxlint 1.80.0で行った。独自ルールの構文上の禁止と完全に同一の検出範囲だとは扱わない。

`consistent-type-assertions`の全面禁止も比較したが、現行テスト内の単独の型アサーション2件にも指摘が出た。今回は型アサーション自体を全面禁止する要求ではないため、採用案に含めない。標準の累積spread検出だけではconcatとObject.assignの問題例が残るので、その不足に限ってanti-slopを使用する。

## 限定試行の結果

| 入力 | 現行lint | 初回の4ルール追加後 | 最終案の3ルール追加後 |
| --- | --- | --- | --- |
| 現行40ファイル | 指摘0件、終了0 | 指摘0件、終了0 | 指摘0件、終了0 |
| 問題例5ファイル | 指摘0件 | 各ファイル1件、計5件を検出 | 各ファイル1件、計5件を検出 |
| 維持したい例5ファイル | 指摘0件 | 指摘0件 | 指摘0件 |

問題例は、連鎖した型アサーション、ローカルconstをunknownに広げた後の型アサーション、reduce内の配列concat、Object.assignによる蓄積結果のコピー、配列spread。維持したい例は、unknown入力のtypeofによる検証、as const、ローカル配列へのpush、入力要素だけのコピー、文字列concatとした。

問題例と維持したい例は同じ10ファイルを各設定で検査した。追加後の終了値1と指摘対象5ファイルの一致を確認した。最初の統合試行では一時設定の置き場所が原因で相対パスの適用範囲が外れたため、その結果を採用せず、設定を対象ルートへ置いて再確認した。ルールが読み込まれた件数だけでは適用成功と判断しない。

この結果は、現行lintに対する追加の検出力と、用意した正常例を妨げないことを示す。現行コードで新しい不具合を発見した結果ではない。実運用全体の誤検出率、性能改善、保守費用の回収は未確認。単発のlint実行時間から性能上の優劣は判断しない。

## 完了条件

実装では次を満たす。

- [ ] 2観点のルールを既存の`bun run lint`へ接続し、違反時に非ゼロ終了する。既存の`bun run check`・CIからも同じ検査を実行する。
- [ ] 型情報を捨てた後の不正な型の付け直し、蓄積結果のspread・concat・Object.assignによる反復コピーを意図した理由で検出する。設定の読込みだけでなく、実際の適用対象で停止することを確認する。
- [ ] unknown入力の値検査と型ガード、as const、新しいローカル配列への追加、入力要素だけのコピー、文字列concatを妨げない。現行の型検査・入力検証を維持する。
- [ ] 新たな指摘が出た場合、実際の不具合と書き方の統一を区別する。外部入力の検証や振る舞いを弱めず、lint無効化によって通過させない。合意した範囲外の規約変更が必要なら、その判断を別途扱う。
- [ ] 独自ルールは標準機能で不足する部分だけに限定し、取り込む原版・ライセンス・更新方法を記録する。OxlintとプラグインAPIの版を揃え、依存をlockfileで固定する。全ルールを有効にする導入スキルは使用しない。
- [ ] 開発方針へ適用範囲と修正例を反映し、`bun run check`・既存の独立評価・日本語確認を通す。最終PR headの`checks`・`verify`成功を確認する。今回の限定試行を採用完了の代わりにしない。

## 実行条件・限界・引き継ぎ

セットアップは既存の`bun install --frozen-lockfile --ignore-scripts`、検証は`bun run check`を使用する。実モデル呼出し、新しい評価基盤、画面変更、定期実行は不要。既存の独立評価・PR作成・人によるマージの経路を用いる。

lintは要求達成や全ての不正な型変換を保証しない。累積コピーの検出も値の増加や実際の処理時間を証明せず、名前付きcallbackや間接的なコピーなど検出範囲外がある。必要なコピーや境界検証まで制約が妨げる事例が出た場合は、具体例と影響を根拠に適用範囲を見直す。

このIssue本文と固定した出典に、実装に必要な範囲・根拠・試行結果をまとめた。別の報告commitや一時試行ディレクトリを実装開始の前提にしない。着手時に対象版の設定・依存・コードを読み直し、既存変更を保全して実装する。
