2つの呼出しが同じ実行記録へアクセスする条件を対象とした。各呼出しは一度だけ開始し、外部コマンドを最大一回起動する抽象モデルである。実際のcheck・repair・reviewの繰り返しは再現せず、コマンド完了から終端保存へ進む成功経路に縮約した。

## モデルと実装の対応

モデルは[RunReservation.tla](formal-state-trial-20260921/RunReservation.tla)。`active`はディスクに保存された予約を表し、実行中のメモリー上の値とは区別した。

| モデルの操作 | 実装で参照した責務 |
| --- | --- |
| Acquire / Release | `run()`が実行記録ごとのロックを取得し、通常の終了・例外時に解放する |
| Inspect | `execute()`が残った`active`を拒否し、終端結果のあるrunで処理を再開しない |
| Reserve / Launch | コマンドを起動する前に`active`を保存する |
| ActorDone / Commit | コマンド終了と、その後の保存を別の段階として扱う |
| Abort | 捕捉された例外・処理可能な割り込みの後、予約を残してロックを解放する |
| Kill | SIGKILLではfinallyが動かず、ロック・予約が残り、子が残る可能性も保持する |

検査したのは、外部コマンドの同時起動がないこと、不確実な予約・実行を残した後に別の呼出しが新しく起動しないこと、終端結果の後に新しく起動しないこと。デッドロック検査は無効にした。停止状態を意図した終端として扱う安全性の試行であり、処理が必ず完了することや自動復旧は評価していない。

## 結果

TLCは幅優先探索、worker数1、seed 1、fingerprint 0、heap上限512MBで実行した。設定は同じディレクトリの5つのcfgに保存している。

| 条件 | TLCの結果 | 異なる状態数 | 経過時間 |
| --- | --- | ---: | ---: |
| 現行設計・新規開始 | 不変条件違反なし、探索完了 | 71 | 0.786秒 |
| 現行設計・終端結果あり | 不変条件違反なし、探索完了 | 16 | 0.823秒 |
| ロックを外す | 外部コマンドの同時起動の反例 | 135 | 1.067秒 |
| 予約保存を起動後へ遅らせる | 不確実な実行後の再起動の反例 | 75 | 0.710秒 |
| 残った予約を無視する | 不確実な予約後の再起動の反例 | 69 | 0.706秒 |

違反がある条件は最初の反例で停止したため、状態数を全探索の結果や条件間の優劣として比較しない。これら3条件は検出力確認用に作った欠陥であり、現行コードで発見した欠陥ではない。

代表的な反例は「呼出しAが予約せず起動 → 終了確認前にAが中断 → ロック解放 → 呼出しBが予約なしと判断 → 同じrunで起動」であった。

### 実コードでの照合

固定版をcheckout外へ取り出し、模擬コマンドと実際の子プロセス・SIGTERMを使った。[probe.ts](formal-state-trial-20260921/probe.ts)が再現手順である。Codex等の外部モデルやGitHub公開は呼んでいない。

- 現行コード: checkの起動を確認してSIGTERMを送り、同じ設定で再呼出しすると残存予約を理由に拒否した。checkの起動記録は1件のままだった。
- `hostCommand()`の予約保存をコマンド終了後へ移した一時コピー: 中断後にも予約が残らず、再呼出しでcheckが起動し、記録は2件になった。
- `execute()`の残存予約の拒否を外した一時コピー: 予約が残っていても、再呼出しでcheckが起動し、記録は2件になった。
- ロックを外した一時コピー: 既存ロックがある終端runを拒否する既存テストが、期待した終了値1に対して0を返すため失敗した。モデルの同時起動の順序を実コードで再現した結果とは区別する。

予約を無視するモデルの最短反例は起動前の中断であり、実コードの試行は起動確認後の中断だった。同じ保護の必要性を異なる停止時点で確かめたもので、全てのモデル反例を同じ順序で実コードへ再生できたとは扱わない。

現行コードの関連テスト8件は2.652秒で全件成功した。既存の`SIGTERM during check preserves reservation and blocks duplicate execution`は予約保存を遅らせたコピーで、`active`が存在しないため失敗した。`terminal success still refuses an active reservation or an existing lock`は、予約拒否を外したコピーとロックを外したコピーで、それぞれ拒否すべき再呼出しが成功するため失敗した。したがって今回の3つの欠陥注入は、既存テストでも検出できる。

## 再実行と保存状態

モデルのSHA-256は`e0ba951442c0b84a7f84ccc4081d5b97c5d0cb0ad766282e8a106709583a089c`。補助ファイルをcheckout外の一時ディレクトリへコピーして実行する。Javaとjarには上記の版を用意する。

```sh
trial_dir=$(mktemp -d)
cp -R docs/research/formal-state-trial-20260921/. "$trial_dir/"
mkdir "$trial_dir/baseline"
git archive e2f19c21b7a450ff967be37524c1cb68cb1bb526 scripts | tar -x -C "$trial_dir/baseline"
bun "$trial_dir/probe.ts"
```

モデル検査は、コピー先を作業ディレクトリとして次の形で実行する。`baseline.cfg`を他の4設定へ変える。TLCの起動にはローカル通信ソケットが必要で、この環境ではsandbox外での実行が必要だった。

```sh
"$trial_java" -Xmx512m -XX:+UseParallelGC -Djava.rmi.server.hostname=127.0.0.1 \
  -cp "$trial_tools" tlc2.TLC -workers 1 -seed 1 -fp 0 \
  -config baseline.cfg RunReservation.tla
```
