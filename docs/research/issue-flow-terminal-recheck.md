## 目的と現状

公開前の安全確認を残し、終了済みrunへの呼び出しで不要な初期化を繰り返さないようにする。

[scripts/development.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/development.ts#L288) は検証終了後もcommit前・push前にverifyを呼ぶ。[scripts/correction.ts](https://github.com/thkt/dotagents/blob/019a25badbcec00a05231267b31fed453a49bf74/scripts/correction.ts#L823) は終端結果を返す前に、Issueの知識参照解析、報告blobの照合、知識JSONの読み込み・抽出を行う。モデルやcheckの再実行は既に省かれている。

## 範囲と完了条件

- [ ] 終了済みrunの照合を初回準備から分け、公開可否の判断に不要な知識の再構成・抽出を省く。既存のstateと照合を利用し、別の証明書・台帳・CLIを追加しない。
- [ ] 保存状態の検査、設定不一致、未完了のactive、lock、現在のIssue・成果物の変化による停止を維持する。

- [ ] 同じ入力では保存済み結果を返し、終端の再照合によって実行回数・記録をリセットしたり、追加のモデル・checkを起動したりしない。

## 重点的な検証・順序

最初に着手する候補。既存の `correction.test.ts`・`knowledge.test.ts`・`development.test.ts` を使い、終端でのIssue／成果物変更、設定不一致、active、参照の不整合が公開に進まないことを確認する。同じ入力では知識の再構成が不要であることも限定した観測で確認する。

## 検証と引き継ぎ

セットアップは `bun install --frozen-lockfile --ignore-scripts`、提出前は引数なしの `bun run check`。既存の関連テストを再利用し、不足する現実的な失敗条件だけを追加・更新する。独立評価と同じPR headの `checks`・`verify` を確認し、人がレビュー・マージを判断する。模擬コマンドの検証、実モデル、実際の公開は別の証拠として報告する。

プロダクト画面媒体は不要。必要な共有根拠はIssueまたは `research/`、内部ログは既存のcheckout外保存先へ置く。既存のrun・失敗記録・他作業の差分を削除・変換せず、新しい必須台帳を作らない。対象・権限・版の照合と、要求変更を人へ戻す責任を維持する。
