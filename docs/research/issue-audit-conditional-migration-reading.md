# implementの移行文書確認を必要な場面に限定する

## 目的と根拠

通常の実装依頼で過去の移行手順まで一律に読み直すように見える指示を整理し、現在の文書確認と、導入・切替時だけ必要な確認を区別する。

確認日: 2026-09-24。対象版: `7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae`。

- [implementの文書確認](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/skills/implement/SKILL.md#L26)は、各担当の日本語確認に続けて、利用先の旧設定と方針を「切替手順」で確認するよう記載している。
- [OUTCOME](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/.codex/OUTCOME.md#L7)は移行手順を毎タスクの前提にしないとしている。[切替手順](https://github.com/thkt/dotagents/blob/7134d2ffa441985ee00d2dd1a6b6e79f5e9cc4ae/scripts/README.md#L470)は旧設定・利用先の方針・旧runの保全・移行の受入確認を扱う。

現行文面の適用条件を明確にする変更であり、毎回の移行検証が実際に発生したという観測ではない。読取量・時間の削減効果は未実測。

## 範囲と対象外

`skills/implement/SKILL.md`の参照条件と、必要な範囲の関連説明を整理する。初回導入、旧版からの切替、旧`writing`設定の検出など、移行手順が必要な条件を明示する。対象repoの設定・方針・登録、runtime、検証定義は変更しない。

## 受入条件

- [ ] 導入済みで旧設定のない通常作業は、現在の日本語確認・文書更新方針を参照して進められ、移行手順全体の毎回読取を要求しない。
- [ ] 利用先への初回適用・旧版からの切替・旧設定の検出では、対象の方針確認と必要な移行手順へつながる。移行済みか不明な場合は確認できる事実を調べ、未確認を移行済みにしない。
- [ ] 旧`writing`入力の拒否、既存の執筆・独立評価・公開後確認、旧run・設定・利用者資産の保全を維持する。
- [ ] 新しい登録台帳・判定gate・モデル呼出しを追加しない。スキル本文の短縮だけを、実行費用の削減と報告しない。

## 検証

通常の文書変更、旧設定を検出した作業、初回の利用先への適用の3場面で、読む資料と停止・判断の境界を原資料へ照合する。セットアップは`bun install --frozen-lockfile --ignore-scripts`。日本語と参照先を既存の独立評価で確認し、変更提出前に`bun run check`、PRでは同じheadの`checks`・`verify`の成功を確認する。文言一致を固定するだけの新規テストや移行の再実行は求めない。実モデルの読取量・遵守を測定していなければ未実測とする。
