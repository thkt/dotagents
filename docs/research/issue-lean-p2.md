## 目的と現状

再評価で過去指摘の全文を書き直す作業と、機械で決まる総合判定の二重回答を減らす。指摘の内容、対象版、修正後の判断と根拠は保持する。

現行ではAIが過去指摘の不変部分まで再出力し、ホストが変更されていないことを検査している。AIが返すaccepted / needs_changesも、必須の未解決指摘と一致するか確認している。

## 範囲と完了条件

- [ ] 過去指摘の不変部分はホストが保持する。AIには過去の全内容と現在の成果物を渡し、各IDに対する現在のdispositionとreason、新規指摘を返させる。対象ID、総評、4観点の評価、参照文書、引き継ぎ事項は維持する。
- [ ] 過去の全IDへの判断をちょうど1件ずつ要求し、欠落・重複・未知IDの更新を拒否する。欠落をfixedやnot_applicableへ変換しない。新規指摘のID、導入対象と初期状態も検証する。
- [ ] 必須かつopenの指摘が残ればneeds_changes、それ以外はacceptedをホストで算出する。targetId照合と、未解決の人の判断を進行可能と扱わない規則を維持する。
- [ ] 完全なレビュー記録をホストで再構成し、過去の本文・履歴、修正ループ、PR本文と引き継ぎを保つ。既存の形式識別を使い、新しい応答形式は新規実行へ適用する。旧runを変換・再開しない。
- [ ] 対象不一致・不正応答・評価失敗では生の応答と対象記録を保持して停止する。repairや文章の意味照合の応答形式は変更しない。並列レビュー、索引、汎用スキーマ基盤は追加しない。

`review.test.ts` と関連するcorrection / developmentの既存検証を使う。fixed、not_applicable、openへの再判断、新規指摘、欠落・重複・対象不一致、必須指摘が残る場合の公開抑止を確認する。AIの総合statusの矛盾だけを検出していたテストは、ホストの算出結果と停止を確認するものへ置き換える。
