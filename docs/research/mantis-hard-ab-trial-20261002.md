## 課題と判定

| 課題 | 残る要求違反、または正しい対照の条件 |
| --- | --- |
| `transform-defect` | GETでの二重復号は直るが、BATCHは検査済み文字列を再復号し、禁止されたprivate文書へ到達する。正常なpercent表現を含む文書名も再復号され、別の文書へ誤解決する |
| `transform-control` | 公開された全経路で復号を1回に揃える。正常な別名・符号化・public内の正規化・順序・重複・空配列を保つ |
| `cache-defect` | tenantごとのキャッシュに直るが、キャッシュhitは現在のuserとACLの確認より先に返り、別主体・権限失効後の読取りを許す |
| `cache-control` | キャッシュ利用前に現在のACLを確認し、本文更新を反映する。正当な再付与、別tenant、空文字本文と別名読取りを保つ |
| `lease-defect` | 拒否後の再試行は直るが、期限切れしたAの成功・拒否後の後処理が、新しく取得したBの所有権を削除する |
| `lease-control` | 所有者tokenが一致する場合だけ後処理で解除する。期限後の再取得、正当な解除、失敗後の再試行、別keyと同期再入の制御を保つ |

要求文には公開入口、信頼する入力主体、復号回数、権限変更の有効時点、期限と解除の意味を明示した。内部関数への直接呼出しは公開経路ではない。leaseの古いworkが期限後も継続すること自体は保証対象外であり、新しい所有権を後処理で壊さないことを判定する。

準備時にモデルを使わず元の不具合、残存欠陥、正常対照を検証した。時計を注入し、Promiseのゲートで操作順を固定した合成データを使う。正常対照の保存テストには主要な要求違反と正常動作を検出する条件を含めた。独立評価でcache-controlの不要な権限変更後の全体キャッシュ無効化が見つかり、起動前に除去し、4コピー・manifestのhash・検証結果を更新した。モデルの結果を見て課題を修正したものではない。ただし実行後、cache-controlに本文キャッシュ自体の冗長性と、不存在の検証がACL拒否で隠れる保存テスト不足が実証された。準備時には見落としていた。機能が正常な対照であって成果物全体が無欠陥とは扱わず、モデル起動後は課題を変更していない。

欠陥課題の主眼は、公開入口からの入力・操作順と残存欠陥を具体的に特定し、必須修正として正しく指摘すること。正常対照の主眼は、必要な正常動作を正しく判断し、誤った必須指摘がないこと。妥当な未知の欠陥・テスト不足・冗長性は個別裁定する。指摘の分割、accepted、check成功、実行完了だけを採点しない。

独立裁定は要求・コード・実出力へ照合し、検証申告が裏付けられるか、hostの裁定資料や他課題へのアクセス、委譲の痕跡も確認する。全24回を分母とし、未完了・実行失敗・裁定不能を充足に含めない。12ペアを候補のみ充足・現行のみ充足・両条件充足・両条件未充足・比較不能に分ける。
