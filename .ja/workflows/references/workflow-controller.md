# ワークフロー制御器

`../core/flow-control.ts`を`code`と`build`の実行動作の正本とする。Codex hook が保存済み状態を現在のタスクに関連付ける。したがって、通常の呼び出しでは`--run-id`を省略する。

## 契約の確認

`codex-flow describe --workflow code`を実行するか、`build`を選ぶ。バージョン付き JSON 結果には、実行定義の雛形と現在の実行段階の契約が含まれる。さらに、強制される順序、指示形式、対応する`report_result`、必要な`evidence_source`が含まれる。

`manifest_template`をリポジトリ外にある実行ごとの一時 JSON ファイルへ複製する。プレースホルダーを置き換え、返された契約から`steps`を埋める。別の固定雛形は保守しない。

呼び出し側は、制御器が推論できない項目だけを選ぶ。対象は実装単位、編集可能ファイル、リポジトリで定義されたコマンド、修正担当である。修正回数の上限と`Ship`の許可も呼び出し側が選ぶ。Red で固定する失敗文字列は、後で調整実行の出力から選ぶ。検証失敗時に停止するゲートでは`owner`を省略し、`blocked`または`triage`を選ぶ。

## 実行時の操作

実行定義の絶対パスを指定して`start`する。その後は`next`と`report`を使用する。返された指示の内容だけを実行する。その`report_result`と要求された証拠を`report`へそのまま渡す。終了指示には`report`しない。

制御器の手順仕様、分類、証拠、終了状態を保持し、文章から再構築しない。
