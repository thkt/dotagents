# Code

計画された各実装単位を、共通の実行制御器を使って機械検証済みの状態へ進める。

実行定義を作る前に、公開された[ワークフロー制御器](../../workflows/references/workflow-controller.md)と[ゲート判定の証拠](../../workflows/references/gate-protocol.md)を読む。

## 判断を準備する

- 実装単位を実行順に並べ、各単位の観測可能な完了状態を決める。
- 各実装単位を Red/Green または Direct に割り当てる。
- Git ルートの絶対パス、編集可能ファイル、ゲートコマンドを決める。
- リポジトリに定義されたコマンドを選び、修正回数の上限を決める。
- 開始前からある依頼範囲外の変更は、すべての`actor`の編集範囲から外す。
- Red で固定する失敗文字列は、調整実行で取得した証拠からだけ選ぶ。どの文字列を証拠にするかは制御器に決めさせない。
- `codex-flow-manifest/v1`の実行定義ファイルを、リポジトリ外の絶対パスへ書く。

## 開始と進行

対象ファイルを編集する前に制御器を開始する。`--run-id`は省略する。Codex hook が現在のタスクに関連付ける。

```bash
codex-flow start --manifest /absolute/path/to/manifest.json
```

以降は公開された`next`と`report`を使う。制御器が終了指示を返すまで、型付き指示に従う。制御器の指示や機械検証結果を文章による判断で置き換えない。

## 完了

`done`だけを完了として扱う。実行定義のハッシュ、ゲート判定の証拠、修正回数を報告する。停止理由と、永続的な Git 操作の有無も報告する。機械検証結果の項目は変更しない。
