# Workflow作成

このパッケージのワークフロー制御、担当処理、ゲート、フック、ワークフロー成果物を変更する依頼では、このリファレンスを読む。

## 所有先

- 維持する完了状態に基づいてモジュールをまとめる。起動・CLI・保存・host 設定は`workflows/runtime/`、汎用処理は`workflows/shared/`、共有実行は`workflows/execution/`、workflow 固有コードは同名のディレクトリに置く。
- ワークフローのテストは所有するワークフローと同じ場所に置く。ワークフロー間または導入環境との境界だけ Integration テストにする。
- Bun 1.4.0 のツールチェーンと依存パッケージの導入先はパッケージルートに置く。

## 実行境界

- 呼び出し元、永続化済み成果物、コマンド、モデルとの境界は、使用前に閉じた型へ変換する。
- 再現可能な検証、権限、状態遷移、再試行、停止条件は TypeScript に置く。
- プロンプトにはコードから導出できない判断だけを書く。信頼しない文章は境界が明確なデータブロックで渡す。
- モデルには完了状態へ到達できる最小限の読み取り、書き込み、ネットワーク、外部操作の権限だけを与える。
- 安定した失敗分類と、宣言された修正担当が判断できる証拠を残す。

## 読みやすさ

- 保守対象の各 TypeScript ファイルは、1 つの`@file Outcome`コメントから始める。
- 名前と型で意図を表す。関数の完了状態または不変条件がシグネチャから分からない場合だけ JSDoc を追加する。
- 同時に変更される知識は 1 箇所に置く。変更理由が独立した類似コードは統合しない。
