# 調査成果

scopingで再利用する調査成果と未採用の提案をGit管理します。報告には、問い、出典と対象版・確認日、結論、適用条件、未解決事項を残します。別の開発者やcloneでも読める参照先を使い、ホスト内の絶対パスだけを根拠にしません。採用した仕様・方針は関連する既存ドキュメントやIssueへ反映します。

保存には[scopingのarchive](../skills/scoping/references/session.md#保存と制約)を使います。現在の根拠が十分な場合だけ、対象checkoutのresearch/へ選んだ報告本文をそのまま保存します。ファイル名は本文のSHA-256から決まり、同じ本文の再保存で重複を増やしません。内容を更新する場合も、更新本文を確認してarchiveし、新しいファイルを参照します。セッションの絶対パスや内部評価は付加しません。本文自体に含まれる情報の公開可否は担当者が確認します。

保存したファイルは自動でcommit・pushされません。[引き継ぎ手順](../skills/scoping/references/session.md#調査成果の引き継ぎ)に従い、確認済みの報告を通常の変更・PRに含めます。実装へ渡すHEADに報告本文が含まれることと、checkoutがcleanであることを確かめます。ローカル保存、コミット、公開を分けて報告し、未公開ならその状態を明示します。

セッション状態・評価・lockはcheckoutとGit管理領域の外に置きます。別worktreeやcloneへの調査成果の共有はGit経由で行い、過去の評価や合意を自動で引き継ぎません。外部保存庫の調査や旧Research資料は一括移管・削除せず、必要な根拠を確認して共有用の報告へまとめます。旧stateの変換・再開は行いません。旧資産の保全条件は[移行と受入](../docs/migration-54.md)を参照してください。
