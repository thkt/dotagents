# Shared Research

Standalone Research publishes public-safe canonical originals in `records/<research_id>.json` and generated views in `reports/<research_id>.md`. These files are unignored for human review and commit. Research does not stage, commit, change branches or refs, push, or publish Issues.

The versionless `codex-research-report` schema permits `research_id` for shared records. Identity is lowercase SHA-256 of the complete parsed report without `research_id`: recursively sort object keys by JavaScript UTF-16 code-unit order, preserve array order and string values, serialize with compact `JSON.stringify`, append one LF, and encode as UTF-8. Stored JSON uses the same serialization with `research_id` included. Historical private reports keep their original format and receive no manufactured IDs.

Markdown is rendered exclusively from parsed canonical JSON, independently of configuration or language. Field paths preserve structure; numeric character references encode presentation syntax and line breaks without changing values. Views are generated and must not be edited directly. `bun run verify:research`, also part of `bun run check`, verifies canonical bytes, embedded and filename identities, exact paired views and filesystem integrity. Only regular pairs, empty `.gitkeep` placeholders and this README are permitted.

Shared publication requires source validation, an independent source audit, deterministic safety checks and a separate read-only semantic safety audit covering every string. Unsafe, uncertain, incomplete or failed checks publish neither file. Publication never rewrites different bytes. An identical complete pair is reused without writes. Interrupted publication retains its identity, accepted bytes and attempt ownership; rerun the same original invocation to reconcile its partial pair. Incomplete pairs are invalid for consumers. A completed invocation can repair a missing Markdown view only from matching canonical JSON and its genuine accepted publication evidence. Divergence or lost acceptance fails closed. Retain incompatible saved state and use its original runtime to recover, or start a new explicit task; no automatic migration occurs.

Automatic Research under Think or Build returns protected private audited evidence, leaving this corpus unchanged. To share it deliberately, start a separately authorized standalone Research invocation with optional `retained_child_report` selecting the original private JSON path. Its completed child state, independent audit, repository and ownership journal must remain available at selection time. Startup captures that original and its historical answers privately. A fresh snapshot, reconsideration, fresh source audit and full public-safety acceptance produce a new original; the retained report remains untouched. There is no copy-only promotion. Clarification answers inform analysis and grant no sharing, Issue or Ship authority.

Knowledge is a replaceable private topic index of these canonical originals, identified by `research_id` and `generated_at`. It contains references, not accumulated summaries. Rebuild validates the complete corpus before replacing the index; invalid pairs or missing previously indexed latest originals leave the prior index unchanged, and lookup omits unavailable originals. The previous index can prevent fallback but supplies no report content; private children, legacy artifacts and configured private roots supply no content. A fresh checkout with committed pairs can rebuild the same references. Explicit Think selectors are canonical JSON filenames relative to `research/records` (or absolute paths to those same files). Think captures complete selected reports first, then at most three related latest originals, with no older fallback when the newest is selected, invalid or unavailable. Dates rank leads; each new invocation verifies claims against its fresh snapshot. Resumes use captured originals and the original snapshot.

Publication staging uses private storage on the corpus filesystem so atomic hard links retain attempt ownership; when the runtime is on another filesystem, the repository’s ignored `.codex/workflow-artifacts` directory holds that staging. Operational state, source and safety audits, answer histories, indexes and temporary publication files remain private. `CODEX_FLOW_ARTIFACT_DIR` scopes private artifacts by repository; it never redirects the shared corpus. Before writing, private storage inside any repository must be Git-ignored and disjoint from tracked files and the corpus. Knowledge rebuilding is best-effort after persistence; failure does not invalidate Research or disclose report content in diagnostics.

This private-storage rule also covers cleanup records, ownership databases and sidecars, restoration staging, private snapshot destinations, actor payloads, SDK runtime roots and temporary credential homes. Establish repository-local ignore policy before invoking a writer; directory-only rules such as `.codex/workflow-artifacts/` work on a fresh checkout. Writers do not create ignore rules. Symlink resolution and the destination repository determine protection, including linked worktrees and saved destinations. Cleanup retains primary-worktree ownership. External storage remains supported. Publication exclusion uses a fixed OS `/tmp/codex-research-publication-locks` namespace keyed by resolved repository and report identity, independent of publishers' `TMPDIR` and artifact settings; unavailable exclusion fails closed.
