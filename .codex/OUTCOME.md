# Project outcome

Provide the shared `scoping` and `implement` workflows for explicitly configured GitHub repositories. Requirements and acceptance belong to the agreed Issue; the host owns execution, verification, publication checks and stop conditions. Humans own approval and merge.

Use `bun run check` for this harness. Product tests and evidence remain in the trial repository. Old workflow state is retained as historical evidence and is never resumed or converted by the new runtime.

The adoption and later registration cutover are tracked in [Issue #54](https://github.com/thkt/dotagents/issues/54). Preparing an adoption PR does not establish completed cutover or fresh-task acceptance.
